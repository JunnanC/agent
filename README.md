# 多Agent智能虚拟化实验平台

本项目面向教学、训练和实验实践场景，建设一套 PC Web 云实验平台。教师基于已发布且不可变的模板版本创建任务并指定用户；平台自动创建容器或虚拟机环境；用户在浏览器工作区完成实验、保存过程并提交报告或成果；教师或评测服务审核；平台在完成成果归档后撤销访问、销毁实例并释放配额。

## 项目定位

平台中的“实验任务”和“实验实例”是两个不同概念：

- **实验任务（experiment_task）**：教师基于已发布且不可变的模板版本创建、并指定到具体用户的任务定义。
- **实验实例（experiment_instance）**：用户基于自己获分配的任务启动的独立运行环境，必须由有效的 `experiment_task_assignment` 触发。

平台不是模板市场、通用云主机控制台、在线刷题平台或无约束聊天工具。普通用户不需要安装本地运行时，也不能自行选择镜像、虚拟机模板、依赖、网络策略或资源规格；普通用户只能进入分配给自己的任务，不能创建模板或自由创建环境。

团队成员资格（`team_memberships`）与账号、固定角色分离：普通用户可申请加入或退出，教师可审核、直接添加或移除成员；**只有 `ACTIVE` 成员能被指定任务**，任务发布与任务启动都要重新校验，退出或移除必须先通过阻断检查并撤销该成员的全部工作区会话。平台为单团队，不建立课程、班级、训练营等二级组织体系。

## 核心闭环

```text
用户申请加入/教师直接添加 -> 成员成为 ACTIVE -> 教师模板/手册
-> 发布并仅指定 ACTIVE 用户 -> 自动装载容器或虚拟机
-> 实验保存 -> 报告或成果提交 -> 审核通过/退回
-> 最终归档 -> 撤销访问 -> 销毁实例和释放配额
```

## 固定四角色

平台采用固定四角色，不做自定义角色；账号、固定角色与成员资格三者分离，也不建立课程/班级/训练营等二级组织体系：

| 角色编码 | 业务身份 | 允许动作要点 | 禁止动作要点 |
|---|---|---|---|
| `USER` | 普通用户 | 申请加入团队、查看本人成员状态、在无阻断事项时退出；查看本人任务、启动/取消装载、使用本人工作区、保存和提交报告/成果、使用受控 Agent、查看审核与归档 | 创建模板、发布任务、编辑环境方案、查看他人任务、管理成员或运行时 |
| `ORG_SUB_ADMIN` | 助教/授权教师 | 在授权任务范围内发布、查看过程、审核和导出 | 审核/添加/移除成员、修改全局配置、越权访问用户、管理固定角色 |
| `ORG_ADMIN` | 教师/团队管理员 | 审核加入申请、直接添加/移除成员；管理模板版本、发布/撤回任务、仅指定 `ACTIVE` 用户、审核、查看授权成果 | 管理运行时底座和全局安全策略 |
| `SYSTEM_ADMIN` | 系统管理员 | 管理账号、固定角色、管理员交接、运行时、镜像/虚拟机模板、配额、补偿、安全和审计 | 代替教师形成业务审核结论、绕过审计修改成果 |

前端路由和按钮只负责可用性，不能替代授权。后端每次读取或写入必须同时校验角色、成员资格、数据范围、资源归属、任务状态、时间窗口和操作权限，不可仅凭资源主键返回数据。

## 逻辑模块与数据所有权

| 模块 | 职责 | 主要数据所有权 |
|---|---|---|
| 身份与授权 | 登录、认证、固定 RBAC、团队成员资格、数据范围、令牌校验 | `users`、`roles`、`team_memberships`、`user_verifications`、`user_quotas` |
| 模板与任务 | 模板草稿/版本、材料、预检、任务发布、仅向 `ACTIVE` 成员分配、撤回、通知 | `experiment_templates`、`experiment_template_versions`、`template_assets`、`experiment_tasks`、`experiment_task_assignments`、`task_materials`、`notifications` |
| 实验编排 | 用户任务状态机、启动幂等、配额锁、装载、事件、归档/销毁的编排与触发 | `experiment_instances`、`instance_provisioning_jobs`、`instance_provisioning_steps`、`instance_events`、`compensation_jobs`、`outbox_events` |
| 运行时网关 | 容器/虚拟机适配、状态、进度、访问、快照、停止、销毁和指标 | 运行时资源映射、实例外部 ID 和能力快照 |
| 工作区网关 | WebIDE、Notebook、终端、远程桌面、Web 预览代理、会话与成员失效会话撤销 | `workspace_access_sessions`、会话审计 |
| 报告与审核 | 报告草稿/版本、附件、提交、评分、退回、证据、成果与归档 | `experiment_reports`、`experiment_report_versions`、`experiment_report_files`、`experiment_report_reviews`、`experiment_archives`、`experiment_archive_files` |
| 记录与产物 | 文件、快照、日志、评测和导出 | `files`、`experiment_records`、`experiment_artifacts`、评测表 |
| Agent 服务 | 上下文组装、模型/工具调用、策略审批、摘要和审计 | Agent/模型/工具调用表 |
| 运维审计 | 运行时白名单、配额治理、告警、保留策略和审计查询 | `audit_logs`、指标、告警 |

**数据所有权唯一性**：每张业务表**只能有一个**归属模块，其他模块一律通过应用服务或领域事件读写。据此明确三处易歧义的归属：`workspace_access_sessions` 归**工作区网关**（身份与授权模块只校验令牌，不拥有会话表）；`experiment_archives`、`experiment_archive_files` 归**报告与审核**（实验编排只做归档与销毁的编排和触发）；`compensation_jobs` 归**实验编排**（运维审计只做补偿任务的查询与处置记录，不拥有该表）。

成员资格校验是身份与授权模块对外的领域服务：任务发布筛选 `ACTIVE` 成员，任务启动在持久化实例事实前重新校验 `ACTIVE`；成员退出或移除成功时发布会话撤销事件，工作区网关消费后撤销该成员的全部活动会话。

模块通过应用服务调用，不直接跨模块更新他人所有的数据表；跨模块变化通过领域事件和 Outbox 传递。

## 技术架构

```text
React 18 + TypeScript 5 + Vite
              |
      Django 5 + DRF（模块化单体）
              |
   --------------------------------
   |              |               |
 MySQL 8.0      Redis 7        MinIO
 业务事实     缓存/队列/锁    报告、快照、日志与归档
                  |
        Celery 5 Worker + Outbox + 补偿任务
                  |
        RuntimeAdapter（统一运行时契约）
             /                    \
    Docker/OCI 容器          libvirt/KVM 虚拟机
                  |
      SSE Gateway（阶段事件、续传与轮询降级）
```

- **前端**：React 18 + TypeScript 5 + Vite，由 OpenAPI 生成客户端类型，页面按 UI 设计文档 **v1.0** 实现响应式和可访问性（D4 关闭）。
- **业务 API**：Python 3.12 + Django 5 + Django REST Framework，单一主业务框架，`drf-spectacular` 生成 OpenAPI 3.0。
- **关系数据库**：MySQL 8.0，使用事务、行锁、JSON、外键和迁移；字段基线为数据库设计文档 **v1.0**（`附件5` 已在库：库名 `agent_virtual_lab`，44 表 + 4 视图 + 3 组触发器（5 个 CREATE TRIGGER 对象）+ 3 存储过程，含 `team_memberships`，D3 关闭）。
- **缓存/队列**：Redis 7 + Celery 5，用于锁、短期会话状态、限流和异步队列；Worker 任务可重试且幂等。
- **对象存储**：MinIO，兼容 S3 API，保存报告正文、附件、快照、日志和归档物；数据库只存元数据和摘要。
- **事件流**：SSE，使用 `event_id`、`Last-Event-ID` 续传和轮询降级；双向工作区由网关代理。
- **运行时**：Docker Engine/OCI 容器与 libvirt/KVM 虚拟机双运行时，统一经 `RuntimeAdapter` 访问，业务服务不直接耦合 Docker、Kubernetes、libvirt 或云厂商 SDK。
- **架构形态**：模块化单体 + 独立 Worker；数据库事务只覆盖本地事实状态、Outbox 和审计，不等待运行时操作完成。
- **一致性**：Outbox 事件与补偿任务；发布任务、报告保存/提交、审核、归档状态变化和会话撤销在同一业务事务内写 Outbox。
- **可观测性**：JSON 结构化日志 + Prometheus 指标 + OpenTelemetry trace，以 `assignment_id`、`instance_id`、`request_id`、`trace_id` 联检。
- **部署**：开发用 Docker Compose；测试、预发布/UAT 与生产按 API、Worker、网关、双 RuntimeAdapter、对象存储和监控分层部署。

`RuntimeAdapter` 契约：

```text
validate_spec(spec)
create(spec, idempotency_key)
get_status(runtime_instance_id)
get_progress(runtime_instance_id)
issue_access(runtime_instance_id, user_id, access_mode)
snapshot(runtime_instance_id, policy)
stop(runtime_instance_id)
destroy(runtime_instance_id, idempotency_key)
collect_metrics(runtime_instance_id)
```

`spec` 必须由服务端将冻结模板版本、任务策略、配额、白名单和安全策略组合生成，不接受普通用户提交的镜像、虚拟机模板、依赖、资源规格、路径或网络规则。

Kubernetes/KubeVirt、PostgreSQL、FastAPI、RQ/Arq、WebSocket 和云厂商运行时属于后续适配或扩展项，不进入第一阶段主实现，不能在代码中同时保留主路径。

## 关键非功能基线

下列数值是第一阶段测试环境和 UAT 的最低验收值，调整必须走需求变更流程：

| 类别 | 基线指标 |
|---|---|
| 容量 | 100 名并发在线用户、50 个并发运行实例、20 个并发环境启动请求 |
| API | 排除文件传输和运行时长任务后，读接口 P95 ≤ 500 ms，普通写接口 P95 ≤ 800 ms |
| 环境启动 | 已缓存镜像条件下容器就绪 P95 ≤ 120 秒；预热虚拟机模板条件下虚拟机就绪 P95 ≤ 300 秒 |
| 事件 | 状态事件产生后 P95 ≤ 2 秒到达；断线后 5 秒内开始续传 |
| 保存 | 报告和工作区自动保存间隔 ≤ 10 秒；已确认保存内容的 RPO ≤ 30 秒 |
| 回收 | 收到销毁指令后 P95 ≤ 5 分钟释放运行时资源 |
| 可用性 | UAT 连续 7 天核心 API 可用性 ≥ 99.5% |
| 恢复 | 关系数据库 RPO ≤ 24 小时、RTO ≤ 4 小时；归档抽样恢复成功率 100% |
| 存储 | 首期对象存储可用容量不少于 1 TB，70%/85% 分级告警，始终保留 15% 安全余量 |
| 兼容性 | Chrome、Edge 最近两个主版本；1440 px 桌面为主验收，920 px 和 390 px 不出现主体横向溢出 |

## 安全与生命周期

- 采用短期访问令牌（数据库只保存 JTI 摘要）和可轮换刷新令牌；实例停止、任务撤回、成员资格失效或销毁时立即撤销活动会话。
- 镜像、虚拟机模板、依赖、网络规则、命令均采用白名单；容器禁止 root、特权模式、宿主路径和 Docker Socket。
- 上传文件执行类型、大小、扩展名、内容扫描和对象摘要校验；报告提交后附件关联不可修改。
- 审计、事件、版本和补偿记录只追加，不原地覆盖；日志、Agent 上下文和终端输出脱敏，凭据不落库。
- 只有归档状态为 `COMPLETED` 且清单 SHA-256 校验通过，才可撤销访问并销毁实例；归档未完成不得销毁。
- 默认保留：报告/成果归档 365 天、审计日志 180 天、运行日志 30 天；教师可在系统上限内延长，不能缩短法定或审计保留期。
