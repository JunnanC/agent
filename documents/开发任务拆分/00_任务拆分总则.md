# 开发任务拆分与执行总则

> 上游设计：`documents/架构设计/00-08`，该目录是唯一架构事实源。  
> 项目基线：绿地（greenfield），从空代码、空数据库和新 API 契约开始。  
> 本目录不包含业务实现代码，也不包含旧系统数据导入、双写或兼容入口任务。

## 一、拆分目标

每个 P 阶段必须形成一个可以独立验收的能力闭环，至少包含：

1. 初始 schema/数据库约束与数据不变量。
2. Django app 的 model、service、selector、permission、API 和异步任务。
3. 所属网页应用或共享前端包的真实 API 接入。
4. 正常、越权、状态冲突、幂等、并发和失败路径测试。
5. 审计、Outbox、trace、metrics 和结构化日志（适用时）。
6. 明确的出口条件、产物版本和未解决阻塞项。

“完成页面”或“接口能返回 200”不能作为阶段完成标准。

  ↓
P07 provisioning 装载作业与 FakeRuntime
  ↓

架构路线中的 `Vxx` 是能力里程碑，本目录的 `Pxx` 是可执行工作包；映射固定如下，避免把编号相近误认为一一对应：

| P01-P02 | V01 core/accounts 与三门户身份 |
| P03-A / P03-B | V02 courses 基础 / V03 courses 增强 |
| P04 | V04 governance |
| P05 | V05 labtemplates/review definitions |
| P06-P08 | V06-V08 同名能力；P07 只做 FakeRuntime，真实适配在 P14 |

| P12 | V11 agents |

| P13-C / P14 | 持续观测收口 / V14 真实基础设施与全链路验收 |

## 三、固定开发工作流

### 3.1 开始前

- 阅读当前阶段文档和架构上游章节，确认上一阶段出口编号已通过。
- 检查工作区改动，不覆盖其他任务的文件。
- 先列出数据不变量、权限矩阵、错误码和测试场景，再实现代码。
- 为当前阶段固定 API/OpenAPI revision 和环境变量清单。

### 3.2 实现中

后端写入顺序固定为：

```text
认证 → Portal/Integration 准入 → 数据范围
→ 幂等记录查询/精确重放 → 状态 guard → If-Match/CAS
→ 行锁 → 业务事务 → 审计 → Outbox → on_commit 外部任务
```

禁止 View/Serializer 直接推进状态，禁止 Worker 复制业务判断，禁止 Django Web 直接访问 Swarm/Docker Socket、MinIO、模型网关或长时外部 I/O。Redis 不承载业务事实，MongoDB 不承载业务审计。

前端接入顺序固定为：

```text
OpenAPI 生成类型 → api-client → Query/Mutation → 页面状态
→ SSE/轮询降级 → 错误/权限/空状态 → 视口验收
```

### 3.3 完成前

- `manage.py check`、格式化、静态检查、类型检查通过。
- 初始 schema 在空 MySQL 上可重复建立，约束和索引有验证测试。
- API、权限、幂等、并发、失败补偿和 OpenAPI 检查通过。
- 相关网页完成 typecheck、lint、build、smoke/E2E 和视口验收。
- 日志、事件、错误响应和浏览器存储无密码、Cookie、Token、签名 URL 或证件原值。
- 更新当前阶段的出口记录；未验证内容必须标记阻塞，不能提前勾选。

## 四、统一 Definition of Done

| 类别 | 标准 |
|---|---|
| 数据 | 表、FK、唯一约束、CHECK、索引、锁顺序和保留策略完成 |
| 后端 | service/selector 分层正确；跨域调用通过公开接口 |
| API | 请求、响应、错误码、状态码、幂等、If-Match 和 portal 已进 OpenAPI |
| 前端 | 真实 API 接入；loading/empty/error/403/409/412/异步状态完整 |
| 安全 | host-only Session、CSRF、对象 scope、脱敏、下载/工作区边界正确 |
| 异步 | Outbox、队列路由、重试、补偿和对账有事实记录 |
| 观测 | trace_id、结构化日志、指标、告警入口可验证 |
| 测试 | 正常、越权、状态冲突、幂等、并发和失败覆盖适用场景 |
| 文档 | 阶段产物、出口、风险和下一阶段输入已更新 |

## 五、目录边界

```text
backend/.../apps/
├─ core/          P01
├─ accounts/      P02
├─ courses/       P03
├─ governance/    P04/P13
├─ labtemplates/  P05
├─ experiments/   P06
├─ provisioning/  P07/P14
├─ workspaces/    P08
├─ reports/       P09
├─ reviews/       P10
├─ archives/      P11
├─ agents/        P12
├─ analytics/     P13
├─ integrations/  P13
└─ notifications/ P13
```

前端固定为 `apps/user-web`、`apps/teacher-web`、`apps/admin-web`，共享包仅允许 `ui`、`api-client`、`auth-client`、`event-client`、`query-keys`、`config` 等无业务权限语义内容。项目不创建 `teams` app，不建立单 SPA 入口。

首期不拆分 LMS 连接器，不建设 Moodle/Canvas/LTI；不交付 PWA、离线通知、独立移动端只读模式、国际化/多语言切换或专项无障碍模块。工作区 IndexedDB 仅用于实验草稿的断网容错，不形成离线应用。
