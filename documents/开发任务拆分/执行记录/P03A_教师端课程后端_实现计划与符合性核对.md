## 三、契约决策（需团队裁决）

| # | 决策 | 依据 | 若需变更的影响面 |
|---|---|---|---|
| 1 | `{staff_id}` 用成员**账号 public_id**，不用自增主键 | doc 08 §1.1 禁止暴露自增主键；doc 07 §五 的 `courses_course_staff` 没有 `public_id`，而 `UNIQUE(course_id, user_id)` 已保证唯一 | 需 doc 07 为 staff 增加 `public_id` 列，并改 `selectors.get_staff` 与路由 |
| 2 | `appoint` 用课程 `row_version`；`staff PATCH`/`grants`/`revoke` 用 staff 行 `row_version` | 与 GET 返回的 ETag 保持一致；任命时 staff 行尚不存在 | 统一改为课程 `row_version` 只需改 3 处 `cas.assert_row_version` |
| 3 | `close`/`archive`/`remove` **不要求** `If-Match` | doc 08 §六 只为 `publish`/`transfer-owner` 标注；§十八 清单为「课程设置、任职/grant、选课审批」。但 doc 02 §七 表述更宽（「状态写要求 If-Match」） | 加严：每个视图补一处 `cas.read_if_match` 与服务入参 |
| 4 | 新增错误码 `IDEMPOTENCY_IN_PROGRESS`(409, retryable) | doc 02 §八 未定义；并发同键复用 `IDEMPOTENCY_KEY_REUSED` 会把客户端合法重试误判为错误 | 若团队要求复用现有码，改 `resolve_idempotency` 两处返回 |
| 5 | 过渡期 actor/资格一律 fail-closed | P02 accounts 未落地；默认放行会让「忘记配置 provider」在生产静默变成越权入口 | P02 落地后注入 `COURSES_ACTOR_PROVIDER` / `COURSES_TEACHER_QUALIFICATION_PROVIDER` |

- 动作：启动 compose 的 mysql 服务，用 integration settings 在**空库**上执行迁移并核对约束。

  1. `manage.py migrate` 在空 MySQL 8.4 上两次连续执行均成功，第二次为 no-op；
