# identity 模块 Spec

## 背景

common 模块已交付并作为平台横切底座。identity 是全平台身份事实源与权限裁决者，负责认证、角色权限、用户认证资料、配额事实与管理端用户治理；不得直接读写其他业务模块的表。

## 目标

- 提供登录、刷新、登出与当前用户查询。
- 实现 common 定义的身份与权限抽象契约，向所有模块提供统一裁决能力。
- 提供系统管理员的用户、权限矩阵与配额管理接口。
- 保证认证凭据不可逆存储、令牌可轮换撤销、写操作幂等且落审计。
- 以测试证明权限矩阵、数据范围、认证状态与配额原子性的关键行为。

## 功能需求

- F1: 认证。`POST /auth/login` 接受用户名与密码，账号有效时返回访问令牌、刷新令牌、有效期、令牌类型与用户身份摘要；失败统一返回未认证错误，不区分账号不存在与密码错误；禁用账号返回账号禁用错误；有效但未加入团队返回需要成员身份错误。
- F2: 令牌轮换。`POST /auth/refresh` 接受刷新令牌并返回新的令牌对；成功后旧刷新令牌立即失效；检测到已轮换刷新令牌重放时，撤销该用户全部活动会话。
- F3: 登出。`POST /auth/logout` 需要访问令牌且幂等，重复调用均成功；仅撤销当前访问令牌及关联刷新令牌，不影响工作区会话。
- F4: 当前身份。`GET /auth/me` 需要访问令牌，返回用户基础信息、状态、成员身份摘要与权限码集合；前端可用其渲染入口，但后端每次请求仍独立鉴权。
- F5: 令牌模型。访问令牌默认 2 小时，刷新令牌默认 7 天；访问令牌包含用户、角色、成员状态与唯一令牌标识；服务端只信任令牌解析结果，不信任请求中的归属声明。
- F6: 权限裁决。实现角色、权限码、数据范围、用户认证状态共同参与判定的领域服务；对外提供动作判定、范围解析、角色查询、会话撤销、配额调整契约，并提供 DRF 权限类。
- F7: 管理用户列表。`GET /admin/users` 仅系统管理员可访问，支持安全分页、关键字、角色、状态与白名单排序；手机号脱敏；软删除用户不可见。
- F8: 用户创建。`POST /admin/users` 仅系统管理员可访问且幂等；单条创建同步完成并初始化默认配额；批量创建返回异步受理信息；重复用户、非内置角色、非法文件均返回既有数字错误码。
- F9: 用户变更。`PATCH /admin/users/{userId}` 仅系统管理员可访问且幂等；可改状态或角色；禁用用户时撤销其活动会话与通知，角色变更立即生效；管理员不可禁用或降级自身；变更写入审计。
- F10: 权限矩阵。`GET /admin/permissions` 仅系统管理员可访问，返回四类内置角色与权限码的只读矩阵；权限由版本化初始化维护，不提供 API 修改。
- F11: 配额查询与调整。`GET /admin/user-quotas/{userId}` 返回上限与已用量；`PATCH /admin/user-quotas/{userId}` 可调整上限；提供给编排模块的原子调整带幂等键并在事务内锁定配额行，防止重复或超额扣减。
- F12: 数据边界。identity 仅拥有 `users`、`roles`、`permissions`、`role_permissions`、`user_verifications`、`user_quotas` 六表；成员身份、团队策略、工作区会话、通知和文件通过外部模块契约访问，不直接读写其表。

## 非功能需求

- N1: 复用 common 的响应、错误码、分页、幂等、审计、Outbox、日志脱敏与 Provider 契约，不实现第二套横切能力。
- N2: 密码必须不可逆强哈希；令牌、密钥、密码不得明文存储；日志与审计不得出现凭据字段。
- N3: 六张表模型均为非托管映射，不生成 migration；字段名严格遵循 V4.0 数据库字段。
- N4: 接口文档中的配额别名仅在序列化层映射，不污染数据库模型。
- N5: 所有写接口启用 common 幂等机制并写审计；认证与权限失败也需可审计。
- N6: 覆盖率不低于 80%，Ruff 检查通过。

## 不做的事

- 不实现工作区访问令牌签发与实例生命周期管理。
- 不直接操作成员、团队、通知、文件或工作区会话表。
- 不实现配额扣减与释放的业务编排语义。
- 不提供自定义角色、权限或权限矩阵修改功能。
- 不在 C10 字段名冲突裁决前实现配额接口别名映射。

## 验收标准

- AC1: 登录成功返回令牌与用户摘要；错误密码、不存在账号、禁用账号、无成员身份账号分别符合约定，且失败信息不泄露账号是否存在。
- AC2: 刷新令牌成功轮换；旧刷新令牌失效；重放旧刷新令牌触发该用户全部活动会话撤销。
- AC3: 登出后旧访问令牌立即失效；重复登出仍成功；工作区会话状态不变。
- AC4: 当前用户接口返回身份、成员摘要、状态与权限码；伪造请求中的用户或角色归属不影响结果。
- AC5: 四种内置角色按权限矩阵逐条断言；无权限或越出数据范围均返回禁止访问，包括直接构造他人资源 ID 的场景。
- AC6: 管理用户列表遵守分页、筛选、排序、脱敏与软删除过滤；仅系统管理员可访问。
- AC7: 单条创建、批量导入、状态或角色变更遵守错误码、幂等、审计与默认配额初始化；重复提交同一批量请求不产生两批用户。
- AC8: 权限矩阵为只读且完整；非系统管理员不可访问。
- AC9: 配额查询返回上限与用量；同一幂等键重复调整不重复生效；并发扣减不越过上限。
- AC10: 用户认证状态与团队策略组合为拒绝时，实验启动相关动作被拒绝；identity 仅通过外部领域服务获取团队策略。
- AC11: Ruff 通过，identity 测试覆盖率不低于 80%，且不新增 migration。
