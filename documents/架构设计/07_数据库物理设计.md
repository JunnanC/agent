# 07 数据库物理设计

> 上游：`01_领域模型与数据设计.md`、`02_后端应用结构与API契约.md`  
> 状态：绿地（greenfield）MySQL 设计草案；字段在初始 schema 评审后定稿

## 一、物理基线

| 项 | 约定 |
|---|---|
| 数据库 | MySQL 8.4 LTS、InnoDB |
| 字符集 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 主键 | `BIGINT UNSIGNED AUTO_INCREMENT`，仅内部使用 |
| 外部标识 | `public_id CHAR(26)` ULID，唯一、ASCII binary collation |
| 时间 | `DATETIME(6)` UTC，API 序列化带时区 |
| 并发版本 | `row_version INT UNSIGNED NOT NULL DEFAULT 1` |
| 摘要/哈希 | SHA/HMAC `CHAR(64) CHARACTER SET ascii COLLATE ascii_bin` |
| 删除 | 业务对象状态化；事实表禁止 UPDATE/DELETE |
| 事实源 | MySQL；Redis 不能作为选课、任务、配额、审核或归档唯一事实 |
| 运行日志 | MongoDB Replica Set；只存结构化运行/访问/安全日志，不存业务事实 |
| 对象 | MinIO/S3 兼容存储；MySQL 只登记 asset、digest、保留期和归属 |

所有 FK 默认 `ON DELETE RESTRICT`。历史操作者字段可 `SET NULL`，账号本身不物理删除。URL/API 禁止接受自增主键。

## 二、公共写语义

| 类型 | 公共列 | 规则 |
|---|---|---|
| Versioned | id、created_at、updated_at、row_version | CAS/If-Match，业务禁止硬删 |
| Mutable | id、created_at、updated_at | 仅低风险投影/偏好 |
| AppendOnly | id、created_at | Web/Worker DB 账号不授予 UPDATE/DELETE；修正靠新事实 |

AppendOnly 至少包括：资格事件、课程任职/grant 事件、选课事件、受众快照、延期决定、任务跃迁、工作区操作/恢复事件、报告版本、Rubric 评分事件、批注修订、审核结论、归档清单/校验、Outbox event、审计、Webhook 投递尝试和 Agent 调用/审批/引用/评测结果。当前状态投影、lease 和 retry schedule 不属于 AppendOnly。

## 四、身份表约束

### `accounts_user`

```text
public_id CHAR(26) UNIQUE
email VARCHAR(254) UNIQUE
username VARCHAR(32) UNIQUE
display_name VARCHAR(64)
account_status VARCHAR(16) INDEX
password VARCHAR(128)
is_active/is_staff/is_superuser BOOLEAN
last_login_at DATETIME(6) NULL
row_version
```

账号表不设置旧版全局业务 `role` 列。平台管理员和教师资格分别由资格表表达，课程内职责由 `courses_course_staff` 表达。

### 教师/管理员资格

`accounts_teacher_qualification` 与 `accounts_platform_admin_assignment`：

- `user_id UNIQUE`。
- status CHECK/应用校验枚举。
- `(status, updated_at)` 索引。
- 授予/暂停/撤销操作者 FK。
- 每次状态变化写对应 AppendOnly event `(qualification_id, id)`。

## 五、课程与任职

### `courses_course`

必备字段：`public_id`、`code`、`title`、summary/description、`owner_id`、status、visibility、enrollment_mode、capacity NULL、报名/教学时间、公共版本列。

约束/索引：

```text
UNIQUE(public_id)
UNIQUE(code)
CHECK capacity IS NULL OR capacity > 0
CHECK enrollment_end > enrollment_start（均非空时）
CHECK teaching_end > teaching_start（均非空时）
INDEX(status, enrollment_start, enrollment_end)
INDEX(owner_id, status, updated_at)
```

### `courses_course_staff`

```text
course_id, user_id, role, status
appointed_by/at, revoked_by/at, row_version
UNIQUE(course_id, user_id)  # 当前任职投影
INDEX(user_id, status, course_id)
INDEX(course_id, role, status)
```

MySQL 无条件唯一约束，课程唯一 OWNER 使用 `owner_slot` 生成列：`role='OWNER' AND status='ACTIVE'` 时为 1，否则 NULL，`UNIQUE(course_id, owner_slot)`。同时 service 锁课程完成交接，并保证 `course.owner_id` 一致。

### `courses_course_staff_grant`

`course_staff_id`、capability、status、expires_at、granted/revoked 操作者、row_version。`UNIQUE(course_staff_id, capability)`；`INDEX(status, expires_at)`。

### 课程内容、互动和批处理

```text
course_chapter: UNIQUE(course_id, position), INDEX(course_id,status,position)
course_material: INDEX(course_id, chapter_id, status, updated_at)
course_material_version: UNIQUE(material_id,version_no), UNIQUE(material_id,content_digest), INDEX(status,published_at)
course_announcement: INDEX(course_id, status, publish_at)
course_calendar_event: INDEX(course_id, starts_at, event_type)
course_prerequisite: UNIQUE(course_id, prerequisite_course_id)
chapter_prerequisite: UNIQUE(chapter_id, prerequisite_type, prerequisite_ref)
course_question: INDEX(course_id, status, updated_at)
course_answer: INDEX(question_id, created_at)
course_invitation: UNIQUE(token_hash), INDEX(course_id,status,expires_at)
enrollment_import_item: UNIQUE(job_id,row_no), INDEX(job_id,status)
course_copy_job: UNIQUE(idempotency_record_id), INDEX(source_course_id,status)
```

先修关系的无环约束由 service 在事务内检查，并由周期性一致性任务兜底。课程复制只保存 source/new course、copy scope、状态、统计和错误引用，不复制 enrollment/task/report 等事实。

## 六、选课

### `courses_enrollment`

```text
public_id CHAR(26) UNIQUE
course_id, student_id
cycle_no INT UNSIGNED
status VARCHAR(16)
application_message TEXT
applied_at, reviewed_by/at, activated_at, ended_at
decision_note, end_reason
live_slot GENERATED:
  CASE WHEN status IN ('PENDING','ACTIVE') THEN 1 ELSE NULL END
row_version
```

约束/索引：

```text
UNIQUE(course_id, student_id, cycle_no)
UNIQUE(course_id, student_id, live_slot)
INDEX(course_id, status, applied_at)
INDEX(student_id, status, updated_at)
CHECK cycle_no > 0
```

`live_slot` 解决 MySQL 不支持条件唯一索引的问题。cycle_no 在锁定 `(course,student)` 的现有行后递增；并发仍由唯一键兜底。

`courses_enrollment_event` 索引 `(enrollment_id,id)`、`(course_id,created_at)`，只追加。

## 七、模板与发布

### 模板

`labtemplates_template`：`course_id`、name、owner、status、current_version，`UNIQUE(course_id,name)`，`INDEX(course_id,status)`。

`labtemplates_template_version`：`template_id`、version_no、status、运行时冻结字段、对象资产 FK、策略、retention_days、spec_digest、row_version。

`labtemplates_auto_check_rule`：`template_version_id`、position、checker_type、input/output schema、timeout、resource_limit、network_policy、display_policy、rule_digest。`UNIQUE(template_version_id,position)`；规则集合参与父版本 `spec_digest`，父版本离开 DRAFT 后禁止 UPDATE/DELETE。

```text
UNIQUE(template_id, version_no)
UNIQUE(template_id, spec_digest)
INDEX(status, published_at)
```

发布/撤回后冻结规格由模型/service 检查；数据库账号限制不能表达字段级冻结，必须有测试。

### `experiments_task_publication`

必备字段：public_id、course/template_version、rubric_version、title/description、audience_mode、late_enrollment_policy、window_start/end、assignment_deadline、report 策略、review_mode（`MANUAL/MANUAL_WITH_AUTO_CHECK`）、status（含 `PUBLISHING/PUBLISH_FAILED`）、发布/关闭/撤回信息、row_version。rubric_version 必须已发布且与 course 同源。

```text
UNIQUE(public_id)
CHECK window_end > window_start
INDEX(course_id, status, window_end)
INDEX(template_version_id, status)
```

`experiments_publication_audience`：publication、enrollment NULL、audience_kind、snapshot_digest、created_at。指定受众时 `UNIQUE(publication_id,enrollment_id)`；只追加。

## 八、个人任务

`experiments_experiment_task` 必备字段：public_id、course/publication/enrollment/student/template_version、runtime_type、status、terminal_target、progress、阶段时间、current_failure、row_version。

```text
UNIQUE(public_id)
UNIQUE(publication_id, student_id)
INDEX(student_id, status, runtime_type, created_at)
INDEX(course_id, status, updated_at)
INDEX(publication_id, status)
INDEX(status, updated_at)
CHECK progress BETWEEN 0 AND 100
```

跨表同课程/学生一致性无法完全用普通 FK 表达，由 service 验证，并由一致性对账扫描。可选增强是使用复合候选键，但会显著增加所有下游 FK 宽度，首期不采用。

`experiments_task_state_transition`：task、from/to、trigger、actor、reason/detail、trace，索引 `(task_id,id)`，只追加。

延期表：request 使用 `(task_id,status,created_at)` 索引；decision 使用 `(request_id,id)` 只追加。任务可维护 `effective_deadline` 投影以便查询，但其来源必须能追溯到 publication 和最新有效 decision。

### Analytics 与 integrations

- analytics 投影均保存 `projection_version`、`source_cursor`、`calculated_at`；重建时写新批次再原子切换 current batch，不能反向修改领域事实。
- risk/recommendation 保存 `explanation_masked`、rule/model version 和 source refs；`UNIQUE(subject, kind, source_digest)` 防重复。
- `integrations_oidc_provider.issuer_hash` 全局 UNIQUE；`integrations_oidc_identity` 冗余 `issuer_hash` 并使用 `UNIQUE(issuer_hash,subject_hash)`，另以 `UNIQUE(provider_id,user_id)` 限制同一 provider 的本地绑定；原始外部 token 不落库。
- API client 只存 `client_id` 和 secret hash；grant 使用 `(client_id,scope,resource_scope)` 唯一。
- `integrations_webhook_endpoint` 保存 URL 加密引用、事件白名单和 secret ref；可变 `integrations_webhook_delivery` 使用 `UNIQUE(endpoint_id,event_id)` 并按 status/next_retry_at 索引，只追加 `integrations_webhook_delivery_attempt` 使用 `UNIQUE(delivery_id,attempt_no)`，保存请求 digest、响应摘要、started/finished_at 和结果。

## 十、事务和锁顺序

统一锁顺序避免死锁：

```text
Course
 → CourseStaff / Enrollment
 → Chapter / Content / ImportJob
 → TemplateVersion / Publication
 → ExperimentTask
 → Quota / Reservation
 → WorkspaceCheckpoint / Review / Archive / ProvisioningJob
```

批量发布按 course/publication 锁定后分片，单个 task 创建依赖唯一键。捕获 deadlock 可有限重试整个 service，但不得在部分外部 I/O 后盲目重试。

## 十一、数据保留与权限

- 应用 DB 账号对 AppendOnly 表只具 `SELECT/INSERT`。
- migration/admin 账号单独保管，不用于 Web/Worker。
- 业务数据不用 cascade delete；账号、课程停用/归档。
- 对象清理先查引用和 retention，再删除 MinIO 对象并追加 purge log。
- 备份包含 schema、数据、binlog 和对象清单；恢复后跑跨表一致性对账。

## 十二、非 MySQL 状态存储

### Redis

Redis 分为明确的逻辑用途，至少使用独立 key 前缀、TTL 和容量告警：

| 用途 | 可否作为事实源 | 规则 |
|---|---|---|
| Cache | 否 | 可淘汰；丢失后从 MySQL 重建 |
| Celery Broker | 否 | 任务载荷只放 ID/trace；定义可接受丢失窗口 |
| SSE Stream | 否 | 只覆盖断线续传窗口，窗口外由 MySQL Outbox 回放 |
| 限流/短锁 | 否 | 过期自动释放；不能替代 MySQL 行锁和配额事实 |

生产环境不得把缓存、Broker 和 SSE 的容量无限混用。Redis 使用 AOF/快照或托管高可用方案，并在恢复验收中验证“Redis 清空后业务状态仍可从 MySQL 重建”。

### MongoDB 运行日志

MongoDB 只接受采集器写入的结构化日志集合，例如 `runtime_logs`：

```json
{
  "created_at": "2026-09-18T06:00:00.000Z",
  "level": "ERROR",
  "service": "celery-provision",
  "portal": "USER",
  "trace_id": "4f9a2c1b7e3d6a80",
  "actor_ref": "01...",
  "course_ref": "01...",
  "resource_type": "task",
  "resource_ref": "EXP-...",
  "action": "swarm.create",
  "result": "FAILED",
  "error_code": "RUNTIME_UNAVAILABLE",
  "duration_ms": 1234,
  "message_masked": "runtime adapter unavailable"
}
```

必备索引和策略：

```text
TTL(created_at, retention_days)
(service, created_at)
(level, created_at)
(trace_id)
(resource_type, resource_ref, created_at)
```

日志由 Fluent Bit/Vector/OTel Collector 从 stdout 批量写入；采集器重试和短期本地缓冲不能阻塞 Web、Gateway 或 Worker。MongoDB 至少采用 3 节点 Replica Set、反亲和和独立持久卷；日志丢失不应改变任务状态，但日志不可用必须触发 P2 告警。审计和不可逆业务操作仍必须在 MySQL `core_audit_log` 中落库。

### MinIO 对象

报告附件、工作区快照、归档包和 Agent 长文本使用 MinIO 版本化对象；MySQL `core_object_asset` 登记对象 key、digest、大小、owner、retention 和扫描状态。数据库备份与对象清单必须成对恢复，禁止把 MongoDB 或 MySQL BLOB 当成大文件主存储。

## 十三、初始 schema 验证

首次建库和每次发布前必须验证：

- 每门课程恰有一个 ACTIVE OWNER 且具有效教师资格。
- 每个 course/student 至多一个 PENDING/ACTIVE enrollment。
- 每个 task 的 course/publication/enrollment/template/student 同源。
- 每个活动实例有非终态 task 和活动 reservation。
- 每个终态 task 无活动工作区和运行实例。
- AppendOnly DB 权限测试通过。
- 新索引在性能种子数据上的执行计划命中预期。
