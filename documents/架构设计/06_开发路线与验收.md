# 06 开发路线、测试与验收

> 上游：`00`～`05`  
> 状态：绿地（greenfield）实施基线；不包含旧系统数据迁移、双写或兼容入口

## 一、实施原则

本项目从空代码基线、空 MySQL、空 Redis、空 MongoDB、空 MinIO 和专用 Docker Swarm 集群开始。旧仓库内容只作为需求参考，不复制旧团队、旧 SPA、旧角色、旧表或旧 API。

这里的“从头开始”指不迁移任何旧业务数据和旧运行实例；本项目 schema DDL/框架建表流程、基础设施初始化脚本和测试种子仍然必须存在，因为它们负责创建本项目自己的空数据库结构。

所有纵切都必须同时交付：

- Django app 模型/初始 schema、service、selector 和权限。
- `/api/v2` OpenAPI、接口测试和生成类型。
- 所属前端页面、loading/empty/error/conflict 状态。
- Celery、Outbox、审计、trace、指标和失败补偿。
- 单元、集成、权限、并发和 E2E 验收。

## 二、首轮决策闸门

以下决策在 V00 结束前确认，确认后直接写入新系统初始 schema 和 OpenAPI；不为未确认内容保留旧兼容字段：

| 决策 | 默认建议 | 影响 |
|---|---|---|
| 选课方式 | 支持 `OPEN`/`APPROVAL`，默认 `OPEN` | 选课、容量与名册 |
| 晚选课任务 | 发布可设置截止前补建 | 任务分配编排 |
| 逾期处理 | 保存可得成果、回收实例、进入 `EXPIRED` | 状态机和归档 |
| 教师资格 | 管理端人工授予 | accounts 与管理端 |
| API Gateway | APISIX/Kong/Traefik 三选一 | 网关路由、限流、观测 |
| Swarm 范围 | 平台服务必用；实验容器经 adapter 调度 | 节点、网络、权限 |
| 状态服务部署 | 外部托管或明确副本/故障切换 | MySQL/Redis/MongoDB/MinIO |
| 日志保留 | MongoDB TTL + 归档 | 日志容量和合规 |
| Agent 检索 | `KnowledgeRetriever` 实现和索引重建策略 | 知识库、引用和评测 |
| 相似度策略 | 支持的成果类型、阈值展示和保留期 | 辅助检查与隐私 |
| OIDC | issuer、账号绑定/解绑、管理员恢复流程 | 单点登录安全 |

  ↓

  ↓

  ↓

## 四、绿地环境初始化

### 4.1 代码与契约

- 建立 Django `core/accounts/courses/labtemplates/experiments/provisioning/workspaces/reports/reviews/archives/agents/governance/notifications/analytics/integrations` 应用。
- 建立 `frontend/apps/user-web`、`teacher-web`、`admin-web` 和共享 packages。
- 生成唯一 `/api/v2` OpenAPI 和 TypeScript 客户端；三端按 tag 导入。
- `/api/v2` 滚动窗口内只发布向后兼容扩展；破坏性变更启用新 major path 或双 revision，不要求三端与后端原子发布。
- 以初始 schema 创建空 MySQL，不创建 `teams` 表，不导入旧数据。

### 4.2 基础设施

- Nginx 提供三个网页 Host 和一个无前端的 `api.example.edu` 机器入口，并配置 TLS、静态文件、SSE/WS、受控下载和上传限制。
- API Gateway 提供 API 路由、限流、超时、熔断、trace 透传，以及按 Host 写入可信 `X-Portal` 或 `X-Auth-Context: INTEGRATION`；两种上下文互斥。
- Swarm 初始化 3 个 Manager，按 `edge/app/worker/runtime/data` 设置节点标签、Secrets、Configs、reservation/limit、健康检查和滚动回滚。
- MySQL、Redis、MongoDB、MinIO 使用独立持久化方案；不依赖单个 Swarm 节点本地目录。
- 每节点部署 Fluent Bit/Vector/OTel Collector；日志脱敏后写 MongoDB Replica Set。

### 4.3 初始化数据

只创建系统必需的幂等 seed：平台安全策略、默认资源规格、默认 Agent 工具策略、保留期、管理员初始化流程。不得写入示例学生、教师、团队或课程作为生产数据；演示数据必须由独立测试命令生成并可清理。

## 五、三端交付

### 用户端

课程目录 → 选课 → 章节/资料/公告/日历/问答 → 学习建议 → 个人实验 → 延期/检查点/增强 Agent → 报告 → Rubric 反馈与归档。

### 教师端

我的课程 → 课程复制/内容/公告/日历/问答 → 名册导入 → 模板/版本 → 实验发布/延期 → 过程追踪 → Rubric/批注/相似度审核 → 教学分析 → Agent 配置 → 成果导出。

### 管理端

总览 → 用户/教师资格/OIDC → 课程监管 → 运行时/镜像/规格 → 配额/成本/预热 → Agent 策略与评测 → API/Webhook → 实例/补偿 → 安全策略 → 审计。

明确不交付 Moodle/Canvas/LTI，PWA、离线通知、独立移动端只读模式，以及国际化/专项无障碍模块。IndexedDB 自动保存作为实验数据容错继续保留，不等同 PWA 离线应用。

三个应用分别构建、测试、发布和回滚；共享包只包含无业务权限语义的 UI、API、认证、事件和工程配置。

## 六、测试策略

| 层 | 比例参考 | 重点 |
|---|---:|---|
| 单元 | 45% | 状态机、资格、课程 scope、容量、冻结字段、blockers |
| 集成 | 35% | service 事务、MySQL、Redis、MongoDB 采集、Outbox、Celery、MinIO、FakeAdapter |
| E2E | 15% | 三站核心旅程、portal 隔离、撤权、工作区、独立发布 |
| 性能/恢复/安全 | 5% | 并发容量、入口链路、Swarm、备份恢复、越权 |

### 6.1 必测并发

- 两名学生争最后一个课程名额，只能一个 `ACTIVE`。
- 同一学生重复选课，只有一个 live enrollment。
- 两名教师同时审批最后名额，一个成功一个容量冲突。
- 发布重试或 Worker 重放不重复生成个人任务。
- 两个 start 请求只创建一个 job、service、instance 和 reservation。
- 两人同时交接负责人，最终恰有一个有效 OWNER。
- 同一 ETag 并发修改课程，一个成功一个 `412`。
- 同一学生的两个延期决定只有一个成为有效投影；课程复制重试不产生重复副本。
- 批量名册逐行幂等，重复执行不产生重复 live enrollment。

### 6.2 必测权限与安全

- 学生不可读取其他学生 task/report/workspace。
- 教师 A 不可读取教师 B 的课程名册和审核。
- 无 grant 助教默认不可见，且不能调用隐藏接口。
- 管理员可监管但不可写业务审核决定。
- USER Session 复制到 TEACHING/PLATFORM 被拒绝。
- 教师资格撤销后旧教师 Session 失效。
- 退课、账号停用和任务终态后旧工作区票据立即失效。
- 浏览器、网关和日志中不出现密码、Cookie、工作区 token、签名 URL 或证件原值。
- Agent 检索不能返回其他课程/未发布资料；无可靠来源时不伪造引用。
- 相似度和风险信号不能自动拒绝、扣分、退课或改变任务状态。
- OIDC issuer+subject 不能被并发绑定到多个账号；Webhook 重放被拒绝。

### 6.3 入口与运行时

- Nginx 正确路由三个 Host，拒绝伪造 `X-Portal`。
- Gateway 对非幂等写请求不自动重试；限流、超时和熔断可验证。
- SSE 禁止 buffering，断线可用 `Last-Event-ID` 续传。
- WebSocket 仅允许 user-web 工作区票据访问。
- Swarm Manager 丢失一个节点仍保持 quorum；服务滚动更新失败可回滚。
- Worker 只能经 adapter 调用 Swarm，Django Web 不挂载 Docker Socket。
- MongoDB 不可用时业务请求仍可完成，但触发日志告警；MySQL 审计不可丢失。

## 七、端到端验收旅程

1. 管理员授予教师 → 教师建课发布 → 学生选课 → 发布实验 → 完成报告 → 教师审核 → 归档销毁。
2. 审批选课与容量并发，确保不超卖、不重复任务。
3. 已发布课程的晚选课按策略补建或明确不分配任务。
4. 有运行任务时退课展示阻断；收口后退课成功。
5. 已启动实验到期，保存成果、撤销会话、销毁运行时后进入 `EXPIRED`。
6. 负责人未交接时撤销资格被阻断；交接完成后撤销并使旧 Session 失效。
7. 三站点独立登录、退出和过期，不能复制 Cookie 跨端使用。
8. Swarm 外部实例与数据库不一致时，对账发现并进入补偿/告警。
9. MySQL、Redis、MongoDB、MinIO 分别执行恢复演练，验证业务和日志边界。
10. 教师复制课程并批量导入名册，学生按章节/先修完成实验、申请延期、创建检查点，教师以 Rubric 和批注审核。
11. 教师配置课程知识库和 Agent，评测通过后发布；学生回答有引用，提示注入和跨课程检索被拒绝。
12. OIDC 登录、开放 API scope、Webhook 签名/重试/死信全链路通过，且不存在 LMS 专用连接器。

## 八、非功能验收

| 指标 | 目标 |
|---|---|
| 读 API | P95 ≤500ms，基于接近生产数据量 |
| 普通写 API | P95 ≤800ms，不含异步外部 I/O |
| 容器/VM 启动 | 缓存容器 P95 ≤120s；预热 VM P95 ≤300s |
| SSE | P95 ≤2s；断线后 ≤5s 开始续传 |
| 自动保存 | 间隔 ≤10s；确认数据 RPO ≤30s |
| 回收 | 销毁指令后 P95 ≤5min 释放资源 |
| 容量 | 100 在线、50 并发实例、20 并发启动 |
| 可用性 | 核心 API 连续 7 天 ≥99.5% |
| 恢复 | MySQL RPO ≤24h、RTO ≤4h；对象和日志抽样恢复 100% |
| Swarm | 3 Manager quorum、节点故障、滚动回滚演练通过 |
| 日志 | MongoDB TTL、查询索引、Replica Set 故障和归档演练通过 |
| 三站交付 | 分别构建/部署/回滚；单站故障不破坏其他站点 |
| 安全 | 跨课程、跨学生、跨 portal 越权用例 0 个通过 |

性能种子由独立测试命令生成：1000 用户、100 教师、100 课程、5000 选课周期、200 模板版本、20000 个人任务和 500 归档。测试完成后销毁测试环境，不进入生产。

## 九、Definition of Done

- 初始 schema、service、selector、API、OpenAPI 和三端页面与文档一致。
- View、Serializer、Worker 不直接推进业务状态或绕过 selector。
- Audit、Outbox、trace、metrics、结构化日志和失败补偿可被测试验证。
- 不存在旧 teams 表、旧单 SPA 入口、旧 v1 路由、旧数据导入脚本或兼容开关。
- 三端覆盖 loading/empty/error/403/409/412/异步状态，且无敏感信息落地浏览器存储或日志。
- Nginx → Gateway → Django → Worker → Swarm/数据服务真实链路通过预发布验收。
- 所有备份、恢复、节点故障和回滚演练有记录。

## 十、风险登记

| 日志泄露敏感数据 | 高 | 采集器脱敏、MongoDB TTL、日志 schema 门禁 |
