# 03 编排、运行时与实时通道

> 上游：`00`～`02`  
> 状态：目标编排设计，复用旧运行时方案并增加课程/选课边界

## 一、队列与职责

| 队列 | 职责 |
|---|---|
| `q_default` | 通知、轻量投影、课程目录刷新 |
| `q_relay` | Outbox 中继、SSE/通知扇出 |
| `q_provision` | Swarm 容器/VM 预检、创建、健康检查和销毁 |
| `q_archive` | 成果打包、校验、保留期清理 |
| `q_compensate` | 课程分配、配额、实例和对象一致性补偿 |
| `q_agent` | 受控 Agent 推理和工具调用 |
| `q_content` | 课程复制、批量名册、资料解析、公告/日历提醒 |
| `q_analytics` | 教学/风险/推荐/质量/资源成本投影 |
| `q_integrations` | Webhook 签名投递、重试和死信 |

长任务 `acks_late=true`、`worker_prefetch_multiplier=1`。Celery task 载荷只传 opaque/数据库 ID 与 trace_id，不传完整对象、凭证或敏感正文。所有 `.delay()`/`apply_async()` 在 `transaction.on_commit` 后执行。

## 二、Outbox 与幂等消费

业务事务写入不可变 `core_outbox_event`，独立 `core_outbox_delivery` 保存投递状态。中继至少一次投递到 Redis Stream/消费者，事件 ID 是幂等键。

```text
Service transaction
 ├─ 更新聚合根
 ├─ 追加业务事件/审计
 └─ INSERT outbox_event
COMMIT
  → relay worker
  → Redis Stream
  → SSE / Notification / Projection / Job consumer
```

Redis 丢失后，中继从 MySQL delivery 投影恢复。事件不能携带 Session、工作区 token、对象签名 URL、证件号或完整报告。

## 三、选课与任务分配编排

课程复制和批量名册先走预检，再执行异步作业：复制不包含学生/任务/成果；导入逐行经过账号、课程容量、重复 enrollment 和邀请码策略校验。部分失败保留逐行结果，不用一个错误回滚全部可成功项目。

### 3.1 开放选课

```text
POST enroll
 → 锁 course
 → 检查报名窗口、账号和容量
 → 建 ACTIVE enrollment + event + outbox
 → commit
 → q_compensate/assignment consumer
 → 扫描仍可补建的 ALL_ACTIVE publication
 → 幂等创建个人 task
 → 通知学生
```

选课成功不依赖异步任务才算成功；个人任务补建可以最终一致，但必须有分配延迟指标与对账。若业务要求选课响应立即显示已有实验，可以在同一事务内同步创建少量任务，仍由异步对账兜底。

### 3.2 审批选课

申请仅建立 `PENDING`，不占容量。教师审批通过时锁课程并重新检查容量；批准、选课事件与 Outbox 同事务。两个教师同时批准最后一个名额时只能一个成功，另一个得到 `ENROLLMENT_CAPACITY_FULL`。

### 3.3 发布实验

```text
教师发布
 → 锁 course/template_version/publication
 → 校验课程任职、课程状态和版本 digest
 → 冻结 audience rule/snapshot
 → 当前 ACTIVE enrollment 批量建 task
 → commit + outbox
 → 分配对账扫描缺口
```

任务唯一键 `(publication_id, student_id)` 使重试安全。批量量级超过单事务阈值时，先冻结 publication 和 audience 并进入 `PUBLISHING`，再由分片 job 建任务；全部分片完成才变 `PUBLISHED`，不可自动修复的失败进入 `PUBLISH_FAILED`。首期容量较小时可同事务批量创建，但接口契约保留异步作业句柄。

## 四、运行时适配器

```python
class RuntimeAdapter(Protocol):
    def preflight(self, spec): ...
    def create(self, spec, idempotency_key): ...
    def status(self, external_id): ...
    def endpoint(self, external_id): ...
    def snapshot(self, external_id): ...
    def destroy(self, external_id, idempotency_key): ...
```

实现：`FakeRuntimeAdapter`、`DockerSwarmAdapter`、可选 `LibvirtAdapter`。Web 进程只创建 `ProvisioningJob`；Worker 通过受控运行时凭证访问 Swarm API，不能挂载 Docker Socket 到 Django。实例标签至少包含 task/course/student opaque id、runtime service id 和创建 trace，便于孤儿对账，但不包含姓名、邮箱或报告内容。

`DockerSwarmAdapter` 必须使用资源 profile 生成 service reservation/limit、节点标签约束、网络策略、健康检查、TTL 和更新/回滚策略。Swarm service id、task id 和外部 endpoint 写入脱敏的 provisioning 事实；真正的配额预留仍在 MySQL。实验容器默认禁止 privileged、默认无出网，并通过工作区网关暴露能力。

### 创建阶段

```text
QUOTA_CHECK
IMAGE_PREPARE
CREATE
NETWORK_ATTACH
BOOT_PROBE
WORKSPACE_READY
```

每个阶段写只追加 `ProvisioningStageEvent`。Adapter 调用有稳定幂等键；Worker 重启不得重复创建实例。

### 销毁阶段

```text
REVOKE_WORKSPACE
OPTIONAL_SNAPSHOT
DESTROY_RUNTIME
VERIFY_ABSENT
RELEASE_QUOTA
FINALIZE_TASK
```

删除外部实例成功但数据库更新失败时创建补偿/对账记录；数据库显示销毁完成但外部实例仍存在是 P1 告警。

## 五、任务启动时序

```text
user-web → POST /tasks/{id}/start
API/service：
  校验 USER portal、本人 task、ACTIVE enrollment、课程/发布窗口
  锁 task，检查无活动 instance/job
  原子预留平台+课程+用户配额
  task → PROVISIONING，创建 job/outbox
  返回 202 + 六阶段骨架
Worker：
  adapter.create/status/endpoint（仅 Worker 调用 Swarm/VM 适配器）
  写阶段事件
  成功 → task READY + SSE
  失败 → failure_record + task FAILED + compensation
```

配额不能只放 Redis。Redis 可做快速限流，最终预留/释放事实在 MySQL。

## 六、截止、撤回与退课

个人延期决定只改变 task 的 effective deadline 投影，不修改 publication 原始窗口。延期批准、驳回、撤销和到期扫描都写只追加决定、Audit 和 Outbox；并发决定用 If-Match/行锁，最新有效决定必须唯一。

### 未启动任务

- 到期：`ASSIGNED → EXPIRED`。
- 教师撤回：`ASSIGNED → CANCELLED`。
- 无实例，无需走销毁，但追加跃迁、审计和通知。

### 已启动任务

不允许直接写终态：

```text
设置 terminal_target=EXPIRED/CANCELLED
 → 禁止新工作区会话
 → 尽可能保存/冻结现有成果
 → ARCHIVING
 → REVOKE_WORKSPACE
 → DESTROYING
 → 释放配额
 → terminal_target
```

归档采用“先尽力归档、运行时限时回收”策略。校验失败先进入补偿和管理端异常队列，保留已生成对象、失败事实和 trace；在安全回收期限内重试，超过期限仍必须撤销工作区、销毁实例并释放配额。此时任务保留 `terminal_target` 并进入 `FAILED`，不得伪装成目标终态；归档补偿成功后再由统一状态服务收口。

常规退课/移除有活动任务时被阻断。紧急账号停用绕过普通交互阻断，但走同一撤销/销毁编排。

## 七、工作区网关

工作区凭证与门户 Session 分离：

| 项 | 规则 |
|---|---|
| 签发者 | `workspaces` service |
| 使用者 | 仅 `user-web` 的 task.student |
| TTL | ≤15 分钟，可在有效 task/enrollment 下续签 |
| 存储 | 数据库仅存 token hash/jti |
| scope | task、student、instance、capabilities |
| 撤销 | 退课、账号停用、任务收口、实例销毁、异常处置立即撤销 |

教师端只能读取工作区快照/进度投影，不能获取学生终端、IDE 或远程桌面票据。管理端只有异常处置，不签发学生工作区 token。

## 八、自动保存

用户端每 ≤10 秒保存，客户端 `client_seq` 单调递增：

```text
浏览器 IndexedDB pending queue
 → API 接收 metadata + 对象
 → ClamAV/类型/大小校验
 → MinIO 保存不可变对象
 → MySQL 更新 latest snapshot CAS
 → Append autosave_log
 → 返回 confirmed_seq
```

服务端拒绝旧 `client_seq` 覆盖新快照，但可识别幂等重传。课程教师只读最终/授权过程快照；报告提交冻结当时 snapshot 引用。

### 检查点与操作回放

学生可在策略允许时创建检查点，系统也可在提交/到期前自动创建。恢复检查点生成新的 snapshot 和恢复事件，不覆盖旧检查点。操作回放只采集高层动作、阶段、工具调用和脱敏错误，不采集原始键盘输入、密码或完整终端输出；教师查看回放必须具备课程过程查看权限并有审计。

## 九、SSE

三个站点各自在本站同源 `/api/v2/events/stream` 建立连接。订阅由 portal 决定：

| Portal | 频道 |
|---|---|
| USER | 本人账号、选课、个人 task、通知 |
| TEACHING | 本人任职课程、名册、publication、review（按 grant） |
| PLATFORM | 平台告警、实例、补偿、审计摘要 |

连接建立、重连和每次敏感事件发送前校验 Session portal 与对象 scope。使用 `Last-Event-ID` 续传、事件 ID 去重；Redis Stream 缺口时从 MySQL 投影补齐或提示客户端全量刷新。

```json
{
  "id": "1726639200000-1",
  "type": "task.status_changed",
  "course_id": "01...",
  "subject_id": "EXP-...",
  "occurred_at": "2026-09-18T14:00:00+08:00",
  "data": {"from": "PROVISIONING", "to": "READY"},
  "trace_id": "4f9a2c1b7e3d6a80"
}
```

前端可用短轮询降级，但不能用定时器推断状态成功。

## 十、补偿与对账

定期检查：

- ACTIVE enrollment 是否缺少应有的开放 publication task。
- task 是否存在重复或跨课程引用。
- PROVISIONING/READY/IN_PROGRESS task 是否有正确实例与配额预留。
- 已终态 task 是否仍有活动工作区/实例/配额。
- 外部运行时实例是否存在对应数据库记录。
- MinIO 对象是否有资产登记，归档 digest 是否一致。
- Swarm service/task 是否存在无对应数据库实例的孤儿资源，数据库实例是否仍绑定活动 service。
- Swarm 节点 reservation/limit 与 MySQL 配额 reservation 是否出现不一致。

可安全自动修复的缺口由补偿 service 处理；不确定或可能丢数据的情况进入 `DEAD` 并在管理端置顶，不自动删除。

## 十一、提醒、分析与外部事件

- 公告定时发布、报名/实验/延期截止提醒由 Beat 扫描事实并写 Outbox，通知消费者幂等投影；不实现 PWA push 或离线通知。
- analytics 消费课程、选课、任务、审核、运行时和 Agent 事件，生成可重建日/小时投影。风险提醒保存规则版本和解释，不能直接修改任务或选课。
- 学习推荐只返回满足资格且可见的课程/章节/实验建议，用户确认后仍走正常选课和启动流程。
- Webhook 消费 Outbox 的最小事件摘要，使用 timestamp + delivery id + HMAC 签名。可变 delivery 保存当前调度状态和 next_retry_at，每次网络尝试追加不可变 delivery_attempt；失败指数退避，超过阈值进入 DEAD，人工重试继续追加 attempt。接收方以唯一 delivery id 做重放保护。
- 实验预热由课程日历和发布窗口触发，Swarm 扩缩容由 governance policy 控制；预热资源有 TTL、硬配额和空闲回收，不为追求启动速度绕过隔离。
