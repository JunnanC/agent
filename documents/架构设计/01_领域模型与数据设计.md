# 01 领域模型与数据设计

> 上游：`00_架构总纲.md`  
> 状态：绿地（greenfield）目标领域设计，尚未实现；数据库从空实例创建初始 schema

## 一、建模原则

1. 账号、平台资格、课程任职、学生选课和个人任务是五种独立事实。
2. 课程是教学数据隔离和授权的聚合根。
3. 历史选课不覆盖；同一学生重新选同一课程产生新的选课周期。
4. 实验任务绑定发布、课程、选课周期、学生和冻结模板版本。
5. 状态与权限使用关系和枚举表达，不将业务事实只放在 JSON。
6. API 使用 ULID/业务码，不暴露数据库自增主键。
7. 可变实体使用 `row_version`，事实流水使用只追加模型。
8. 公告、章节、资料、日历、问答和先修关系都归属于课程，不能跨课程隐式共享可写数据。
9. 分析、推荐、风险和成本数据是可重建投影，不反向成为任务、审核或配额事实。
10. Agent 知识索引是可重建派生数据，知识源版本、权限、引用和评测事实保存在 MySQL/MinIO。

## 二、关系总览

```text
User
 ├─ TeacherQualification
 ├─ PlatformAdminAssignment
 ├─ CourseStaff ───────────────┐
 └─ Enrollment ─────────────┐  │
                            ▼  ▼
                          Course
                            │
             ┌──────────────┴──────────────┐
             ▼                             ▼
       LabTemplate                   TaskPublication
             │                             │
       TemplateVersion ────────────────────┤
                                           ▼
 Enrollment ─────────────────────── ExperimentTask
                                           │
                      ┌──────────┬─────────┼────────┬─────────┐
                      ▼          ▼         ▼        ▼         ▼
                  Instance   Workspace   Report   Review   Archive
```

任何 `ExperimentTask` 都必须满足：

```text
task.course_id
  = task.publication.course_id
  = task.enrollment.course_id
  = task.template_version.template.course_id

task.student_id = task.enrollment.student_id
```

数据库 FK 保证对象存在，服务层在事务内保证跨表同课程不变量。

## 三、账号与平台资格

### `accounts_user`（Versioned）

账号只表达身份与可登录状态，不再用单值 `role` 决定全部业务能力。

| 字段 | 说明 |
|---|---|
| `public_id` | 26 位 ULID，唯一 |
| `email` / `username` / `display_name` | 登录与展示身份 |
| `account_status` | `ACTIVE` / `DISABLED` |
| `password` | Argon2 哈希 |
| `is_staff` / `is_superuser` | 仅 Django 运维用途，不直接作为业务授权 |
| `row_version` | 资料和停用并发控制 |

所有 `ACTIVE` 账号可进入用户端，但课程内容访问仍需有效选课。账号停用立即阻止三端登录、撤销 Session/工作区票据并触发运行资源对账；不删除历史。

### `accounts_teacher_qualification`（Versioned）

| 字段 | 说明 |
|---|---|
| `user` | OneToOne User |
| `status` | `ACTIVE` / `SUSPENDED` / `REVOKED` |
| `granted_by/at` | 管理员授予 |
| `suspended_by/at`、`revoked_by/at` | 管理动作 |
| `reason` | 必填、脱敏 |
| `row_version` | 并发保护 |

另建只追加 `accounts_teacher_qualification_event`。教师资格只允许进入教师端和创建课程，不自动授予任何课程的数据权限。撤销前必须检查其负责课程并完成负责人移交；紧急暂停可立即禁止教师端访问，但课程历史不变。

### `accounts_platform_admin_assignment`（Versioned）

平台管理员资格独立于教师资格。字段与教师资格类似，状态为 `ACTIVE/REVOKED`，变更写只追加事件。平台管理员可以同时拥有教师资格，但进入不同网站时按门户和对象权限执行，不可在管理端作出课程审核结论。

### 身份资料

`accounts_identity_verification` 继续保存学校/企业认证资料。认证通过不自动生成教师资格；证件号只保存 HMAC 和掩码，材料使用 `core_object_asset`。

## 四、课程聚合

### `courses_course`（Versioned，聚合根）

| 字段 | 说明 |
|---|---|
| `public_id` | ULID，外部路径标识 |
| `code` | 唯一业务码，如 `COURSE-2026-AI-001` |
| `title` / `summary` / `description` | 课程信息 |
| `owner` | 当前负责人；必须具有有效教师资格 |
| `status` | `DRAFT` / `PUBLISHED` / `CLOSED` / `ARCHIVED` |
| `visibility` | `PUBLIC` / `UNLISTED` |
| `enrollment_mode` | `OPEN` / `APPROVAL` |
| `capacity` | NULL 表示不设课程容量；否则正整数 |
| `enrollment_start/end` | 报名窗口 |
| `teaching_start/end` | 教学时间 |
| `row_version` | 设置与状态更新并发控制 |

状态规则：

```text
DRAFT ──发布──▶ PUBLISHED ──关闭──▶ CLOSED ──归档──▶ ARCHIVED
  ▲                 │
  └────撤回编辑──────┘  # 仅无已生效发布/任务时允许
```

- `DRAFT` 只对课程任职人员可见。
- `PUBLISHED` 可报名并可发布实验。
- `CLOSED` 不接收新选课和新实验，已有任务按策略收尾。
- `ARCHIVED` 只读；必须无活动实例、待审核、归档和销毁作业。

### `courses_course_staff`（Versioned）

| 字段 | 说明 |
|---|---|
| `course` / `user` | 任职对象 |
| `role` | `OWNER` / `ASSISTANT` |
| `status` | `ACTIVE` / `REVOKED` |
| `appointed_by/at`、`revoked_by/at` | 任职生命周期 |
| `row_version` | 并发保护 |

每门课程恰有一个有效 `OWNER`，且与 `course.owner` 一致。负责人交接在同一事务内锁定课程和相关任职。助教默认无选课审批、审核、导出等高风险权限，具体能力由固定枚举 grant 授予。

### `courses_course_staff_grant`（Versioned）

固定能力：`MANAGE_ENROLLMENT`、`MANAGE_CONTENT`、`MODERATE_QA`、`MANAGE_TEMPLATE`、`PUBLISH_EXPERIMENT`、`MANAGE_EXTENSION`、`VIEW_PROGRESS`、`REVIEW_SUBMISSION`、`EXPORT_RESULT`、`MANAGE_AGENT`。唯一约束 `(course_staff, capability)`；grant 可撤销/过期，不能授予课程外对象。

### 课程内容与互动

| 聚合/表 | 核心语义 |
|---|---|
| `courses_course_chapter` | 课程章节、顺序、发布状态；章节可关联资料和实验发布 |
| `courses_course_material` | 资料聚合身份、章节归属和当前发布版本 |
| `courses_course_material_version` | 文件/链接/正文的不可变版本，绑定 `core_object_asset`、digest、状态和发布时间 |
| `courses_course_announcement` | 草稿、定时发布、置顶、过期和通知策略 |
| `courses_course_calendar_event` | 报名、实验、延期、审核等课程日历投影，可由领域事件生成 |
| `courses_course_prerequisite` | 课程间先修关系；发布前检查环路，不能形成循环依赖 |
| `courses_chapter_prerequisite` | 章节/实验前置条件，引用已完成任务、审核结果或章节 |
| `courses_course_question`、`courses_course_answer`、`courses_course_moderation_event` | 课程问答、已解决、置顶、隐藏/举报和审核历史 |

章节采用 DRAFT/PUBLISHED/WITHDRAWN 状态；已被发布或实验引用的章节不能物理删除。资料发布冻结具体 `material_version`，修改已发布资料必须创建新版本，历史实验、Agent 引用和审核仍指向原版本。

课程复制使用异步 `courses_course_copy_job`：复制课程结构、章节、资料引用策略、模板、Rubric 和 Agent 配置，但不复制学生、选课、个人任务、报告、审核、工作区或运行实例。复制结果必须生成全新 public_id、模板版本和对象引用关系，并记录来源。

### 邀请与批量名册

`courses_course_invitation` 保存短期邀请码的 hash、scope、使用次数和过期时间；`courses_enrollment_import_job`、`courses_enrollment_import_item` 保存 CSV 预检、逐行错误和执行结果。导入先预检后确认，真正激活仍锁定课程并执行容量、重复选课和账号状态校验。

## 五、选课聚合

### `courses_enrollment`（Versioned）

| 字段 | 说明 |
|---|---|
| `public_id` | ULID |
| `course` / `student` | 课程和学生账号 |
| `cycle_no` | 同一学生在同一课程的选课周期号 |
| `status` | `PENDING` / `ACTIVE` / `REJECTED` / `WITHDRAWN` / `DROPPED` / `REMOVED` |
| `application_message` | 可选申请说明 |
| `applied_at` / `reviewed_by/at` | 申请与审批 |
| `activated_at` / `ended_at` | 有效期 |
| `decision_note` / `end_reason` | 决策理由 |
| `row_version` | 审批/退出并发控制 |

```text
OPEN：       新申请 ─────────────▶ ACTIVE
APPROVAL：   新申请 ─▶ PENDING ─▶ ACTIVE / REJECTED / WITHDRAWN
ACTIVE：                         ─▶ DROPPED（本人）/ REMOVED（教师）
```

每次重新申请建立新行，不把旧 `REJECTED/DROPPED/REMOVED` 改回 `PENDING`。MySQL 使用生成列 `live_slot`：状态在 `PENDING/ACTIVE` 时为 `1`，否则 NULL，并建立 `UNIQUE(course_id, student_id, live_slot)`。

容量只统计 `ACTIVE`。开放选课或审批通过时锁定课程行并重新计算容量；前端显示的余量不能作为事实。

### `courses_enrollment_event`（AppendOnly）

保存 `enrollment`、`from_status`、`to_status`、`actor`、`reason_code`、`blockers_snapshot`、`trace_id`。它是名册历史和学生选课记录的事实源。

课程邀请和批量导入只改变“如何发起选课”，不绕过 enrollment 的容量、唯一约束、课程状态和事件流水。

### 退出/移除阻断

常规退课和移除前检查：

| 阻断 | 条件 |
|---|---|
| `UNFINISHED_TASK` | 存在非终态个人任务 |
| `RUNNING_INSTANCE` | 存在创建中、运行中或销毁中实例 |
| `PENDING_REVIEW` | 存在未关闭审核 |
| `ARCHIVING_IN_PROGRESS` | 存在排队/执行中的归档 |
| `DESTROYING_IN_PROGRESS` | 存在排队/执行中的销毁 |

检查接口只供展示；实际 drop/remove 必须在事务中再次检查。账号紧急停用不受常规阻断限制，但必须撤销访问并创建补偿清理，不能删除选课/任务历史。

## 六、课程模板

### `labtemplates_template`（Versioned）

归属于唯一课程，字段包括 `course`、`name`、`category`、`description`、`owner`、`status`、`current_version`。唯一约束 `(course, name)`。跨课程复用采用复制生成新模板，不共享可写模板。

### `labtemplates_template_version`（Versioned + 字段冻结）

版本保存运行时类型、适配器、镜像 digest、资源规格、依赖、网络策略、工作区能力、实验手册、起始资源、报告/审核策略、保留期和 `spec_digest`。

`labtemplates_auto_check_rule` 绑定唯一模板版本，保存 checker 类型、输入/输出 schema、超时、资源上限、网络策略、展示策略和 position。规则集合参与 `spec_digest`；父版本进入 PRECHECKING 后即冻结，修改只能 clone 新模板版本。

```text
DRAFT → PRECHECKING → PRECHECK_PASSED → PUBLISHED → WITHDRAWN
                   └→ PRECHECK_FAILED
```

只有预检通过且 digest 未变化的版本可发布。`PUBLISHED/WITHDRAWN` 后规格字段不可修改，只能 clone 新版本。

Rubric 定义是实验发布的前置配置：`reviews_rubric`、`reviews_rubric_version`、`reviews_rubric_criterion` 在模板阶段建立并发布冻结版本；评分事实、批注和审核决定仍在审核阶段产生。

## 七、课程实验发布

### `experiments_task_publication`（Versioned）

| 字段 | 说明 |
|---|---|
| `course` | 唯一归属课程 |
| `template_version` | 同课程且已发布、预检通过的冻结版本 |
| `title` / `description` | 本次课程实验信息 |
| `audience_mode` | `ALL_ACTIVE` / `SELECTED` |
| `late_enrollment_policy` | `ASSIGN_UNTIL_DEADLINE` / `DO_NOT_ASSIGN` |
| `window_start/end` | 启动和提交窗口 |
| `assignment_deadline` | 晚选课补建截止 |
| `report_required` / `review_mode` | 本次发布策略；`review_mode` 仅允许 `MANUAL` / `MANUAL_WITH_AUTO_CHECK` |
| `rubric_version` | 同课程、已发布的冻结 Rubric 版本；每个发布必须绑定 |
| `status` | `DRAFT` / `PUBLISHING` / `PUBLISHED` / `PUBLISH_FAILED` / `CLOSED` / `WITHDRAWN` |
| `published_by/at` | 发布者必须有本课程权限 |
| `row_version` | 并发控制 |

### `experiments_publication_audience`（AppendOnly）

当 `audience_mode=SELECTED` 时，记录发布时选择的 `enrollment_id`；当为全员时记录受众规则和发布快照摘要。受众不能随教师刷新当前名册而隐式变化。

少量受众时，发布事务创建 publication、受众事实、当前个人任务、跃迁、审计和 Outbox。受众较多时先冻结为 `PUBLISHING`，由分片作业创建任务，全部成功后进入 `PUBLISHED`，不可自动修复的失败进入 `PUBLISH_FAILED` 并保留失败/补偿记录。任务创建唯一约束保证重放安全；异步对账补偿批量分配中的缺口。

## 八、个人实验任务

### `experiments_experiment_task`（Versioned，状态机聚合根）

| 字段 | 说明 |
|---|---|
| `public_id` | 业务标识 |
| `course` / `publication` | 课程与发布 |
| `enrollment` / `student` | 选课周期和执行者 |
| `template_version` | 冻结环境版本 |
| `runtime_type` | 从版本冗余复制，便于筛选 |
| `status` | 任务状态 |
| `terminal_target` | NULL / `COMPLETED` / `CANCELLED` / `EXPIRED` |
| `progress` | 展示投影，不作为状态事实 |
| 阶段时间 | started/ready/submitted/reviewed/archived/completed |
| `current_failure` | 最近失败记录 |
| `row_version` | 状态并发控制 |

唯一约束 `(publication, student)`。`enrollment` 必须是发布课程中该学生的有效选课周期。

### 状态枚举

```text
ASSIGNED → PROVISIONING → READY → IN_PROGRESS

报告必交：IN_PROGRESS → REPORT_DRAFT → UNDER_REVIEW
报告非必交：IN_PROGRESS ────────────→ UNDER_REVIEW

UNDER_REVIEW → APPROVED / REJECTED
REJECTED → REPORT_DRAFT（报告必交）或 IN_PROGRESS（非报告）
APPROVED → ARCHIVING → DESTROYING → COMPLETED

未启动撤回：ASSIGNED → CANCELLED
未启动逾期：ASSIGNED → EXPIRED
已启动撤回/逾期：当前态 → ARCHIVING → DESTROYING → terminal_target
任意异步步骤失败：→ FAILED；恢复时回到 failure.previous_status
```

终态为 `COMPLETED/CANCELLED/EXPIRED`。已创建实例的任务不能直接进入终态；必须撤销工作区、尽可能归档、销毁实例和释放配额后，再按 `terminal_target` 收口。归档校验失败会阻止任务伪装成目标终态，但不能让运行实例超过安全回收期限继续存活；超期时先销毁实例、释放配额并保留 `FAILED + terminal_target`，待归档补偿成功后由统一状态服务收口。

### `experiments_task_state_transition`（AppendOnly）

记录 `task`、前后状态、trigger、actor、reason、detail_masked、trace_id。状态跃迁只由统一 service 执行。

### 延期、补交与学习路径

`experiments_task_extension_request` 保存申请人、原截止、申请截止、理由和状态；`experiments_task_extension_decision` 只追加保存教师决定。任务的有效截止时间由发布窗口与最新有效延期计算，不直接覆盖 publication 历史值。教师可主动授予延期，也可审批学生申请；所有决定要求课程 `MANAGE_EXTENSION` 权限。

发布可引用 `courses_chapter_prerequisite` 或前置 publication。启动时服务层重新校验前置任务是否达到要求状态。学习建议只生成推荐投影，不自动选课、分配任务或改变状态。

## 九、下游聚合关联

| 领域 | 与课程化模型的关联 |
|---|---|
| provisioning | Instance/Job 绑定个人 task；配额同时记录 course/student |
| workspaces | Session 绑定 task + student，签发时重验 enrollment/task/portal |
| reports | Draft/Version 绑定 task；只有 task.student 可写 |
| reviews | Review 绑定 task；决定人必须有 task.course 的审核权 |
| archives | Archive/Manifest 绑定 task；课程教师只读本课程成果 |
| agents | Session 绑定 course + enrollment + student + profile；课程问答 task 可空，其他模式必须绑定本人 task |
| notifications | 接收人和 course/task 作为可见性投影，读取时仍校验对象权限 |
| analytics | 从领域事件生成课程进度、风险、质量、推荐和资源成本投影；可丢弃重建 |
| integrations | OIDC 身份映射、开放 API client/scope、Webhook endpoint/delivery；不拥有业务状态 |

### 工作区增强

`workspaces_workspace_checkpoint` 保存学生主动或策略触发的快照引用、digest、来源 seq 和保留期；恢复检查点必须创建新恢复事实，不覆盖旧检查点。`workspaces_operation_event` 只记录允许的高层操作事件和脱敏摘要，用于受控回放，不记录原始按键、密码、Token 或完整终端内容。

### 审核增强

Rubric 使用 `reviews_rubric`、`reviews_rubric_version`、`reviews_rubric_criterion` 表达冻结评分量规，publication 绑定具体版本。`reviews_criterion_score` 是带 row_version 的当前投影，`reviews_criterion_score_event` 只追加保存每次修订；`reviews_review_annotation` 以追加修订/撤销事实保留完整历史，`reviews_auto_check_run` 保存自动检查事实。`reviews_similarity_run`、`reviews_similarity_match` 保存成果相似度候选、算法版本和解释摘要；自动检查与相似度都不得自动产生 APPROVE/REJECT 决定，必须由有权限教师复核。

### 分析与开放集成

`analytics_course_daily`、`analytics_student_risk_signal`、`analytics_course_quality_snapshot`、`analytics_learning_recommendation`、`analytics_resource_cost_daily` 都是从 MySQL 领域事实和资源计量生成的可重建投影。风险和推荐必须保存 rule/model version、解释和来源事实，不写回原任务状态。

`integrations_oidc_provider`、`integrations_oidc_identity`、`integrations_api_client`、`integrations_api_client_grant`、`integrations_webhook_endpoint`、`integrations_webhook_delivery`、`integrations_webhook_delivery_attempt` 分别支持 OIDC、scope 化开放 API 和签名 Webhook。`integrations_webhook_delivery` 是可变调度投影，`integrations_webhook_delivery_attempt` 是只追加投递事实；只发送最小事件摘要，具备签名、重放保护、退避和死信。首期不实现 Moodle、Canvas、LTI 或成绩回传。

### Agent 知识与评测

| 聚合/表 | 语义 |
|---|---|
| `agents_course_profile` | 课程级 Agent 模式、可用知识库、工具集合、预算和生效版本 |
| `agents_knowledge_base`、`agents_source`、`agents_source_version` | 课程知识库、资料来源、解析状态、权限和内容 digest |
| `agents_ingestion_run` | 文档解析、切分、索引和失败记录；索引可重建 |
| `agents_prompt_template`、`agents_prompt_version` | 平台基线提示词与教师允许配置区分离；生效版本冻结 |
| `agents_retrieval_trace`、`agents_citation` | 检索源版本、片段引用、分数和最终回答中的引用位置 |
| `agents_eval_suite`、`agents_eval_case`、`agents_eval_run`、`agents_eval_result` | 离线评测、越权/注入/引用/工具安全回归和发布门禁 |
| `agents_session_feedback` | 学生有用性反馈、教师问题标记和纠正建议 |

向量/混合检索通过 `KnowledgeRetriever` 端口实现；索引只存派生向量与 opaque source_version id，必须能从 MySQL 元数据和 MinIO 原文重建。模型回答在知识问答模式下必须返回可访问来源引用；无可靠来源时明确降级，不伪造引用。

agent.knowledge.indexed / agent.eval.completed
