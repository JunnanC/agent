# 03 技术路线与系统架构

**版本：** v1.0  
**状态：** 待审核的候选开发基线

## 1. 已冻结架构原则

1. 第一阶段采用模块化单体加独立 Worker；模块接口、数据所有权、事务边界和异步边界必须明确。
2. 浏览器只访问平台网关，不直接暴露容器端口、虚拟机管理 API、Kubernetes API 或对象存储管理凭据。
3. 业务服务不直接耦合 Docker、Kubernetes、libvirt 或云厂商 SDK，统一经 `RuntimeAdapter` 访问。
4. 长耗时工作使用 Celery 异步任务和 SSE 事件；数据库事务只覆盖本地事实状态、Outbox 和审计，不等待运行时操作完成。
5. 所有外部调用具备超时、有限重试、幂等键、链路追踪、结构化日志、告警和补偿。
6. 关系数据库是业务事实来源；Redis 只承担缓存、短期状态、锁、限流和队列，不保存唯一事实。

## 2. 第一阶段冻结技术栈

| 层级 | 冻结方案 | 实施约束 |
|---|---|---|
| Web 前端 | React 18 + TypeScript 5 + Vite | 由 OpenAPI 生成客户端类型；页面按 UI v1.0 实现响应式和可访问性 |
| 业务 API | Python 3.12 + Django 5 + Django REST Framework | 单一主业务框架；drf-spectacular 生成 OpenAPI 3.0 |
| 关系数据库 | MySQL 8.0 | 使用事务、行锁、JSON、外键和迁移；字段基线为数据库设计文档 v1.0（`documents/Preparation/附件5`） |
| 缓存/队列 | Redis 7 + Celery 5 | 锁、短期会话状态、限流、异步队列；Worker 任务可重试且幂等 |
| 对象存储 | MinIO，兼容 S3 API | 报告正文、附件、快照、日志和归档物；数据库只存元数据和摘要 |
| 事件流 | SSE | 使用 `event_id`、`Last-Event-ID` 续传和轮询降级；双向工作区由网关代理 |
| 容器运行时 | Docker Engine/OCI | 非特权用户、只读底层文件系统、资源限制、网络白名单、无宿主路径和 Socket 暴露 |
| 虚拟机运行时 | libvirt + KVM | Cloud-init、模板白名单、系统盘快照、远程桌面/Web 终端和凭据撤销 |
| 可观测性 | JSON 结构化日志 + Prometheus 指标 + OpenTelemetry trace | 以 `assignment_id`、`instance_id`、`request_id`、`trace_id` 联检 |
| 测试工具 | pytest、Django test、Playwright、k6、OWASP ZAP | 统一纳入 CI 质量门禁 |

Kubernetes/KubeVirt、PostgreSQL、FastAPI、RQ/Arq、WebSocket 和云厂商运行时属于后续适配或扩展项，不进入第一阶段主实现，不能在代码中同时保留主路径。

## 3. 逻辑模块与数据所有权

| 模块 | 职责 | 主要数据所有权 |
|---|---|---|
| 身份与授权 | 登录、认证、固定 RBAC、成员资格、数据范围、短期会话 | `users`、`roles`、`team_memberships`、`user_verifications`、`user_quotas` |
| 模板与任务 | 模板草稿/版本、材料、预检、任务发布、仅向ACTIVE成员分配、撤回、通知 | `experiment_templates`、`experiment_template_versions`、`template_assets`、`experiment_tasks`、`experiment_task_assignments`、`task_materials`、`notifications` |
| 实验编排 | 用户任务状态机、启动幂等、配额锁、装载、事件、归档/销毁协调 | `experiment_instances`、`instance_provisioning_jobs`、`instance_provisioning_steps`、`instance_events`、`compensation_jobs`、`outbox_events` |
| 运行时网关 | 容器/虚拟机适配、状态、进度、访问、快照、停止、销毁和指标 | 运行时资源映射、实例外部 ID和能力快照 |
| 工作区网关 | WebIDE、Notebook、终端、远程桌面、Web 预览代理和会话 | `workspace_access_sessions`、会话审计 |
| 报告与审核 | 报告草稿/版本、附件、提交、评分、退回、证据和成果 | `experiment_reports`、`experiment_report_versions`、`experiment_report_files`、`experiment_report_reviews`、`experiment_archives`、`experiment_archive_files` |
| 记录与产物 | 文件、快照、日志、评测、归档和导出 | `files`、`experiment_records`、`experiment_artifacts`、评测表 |
| Agent 服务 | 上下文组装、模型/工具调用、策略审批、摘要和审计 | Agent/模型/工具调用表 |
| 运维审计 | 运行时白名单、配额治理、告警、补偿、保留和审计查询 | `audit_logs`、指标、告警和补偿记录 |

模块通过应用服务调用，不直接跨模块更新他人所有的数据表；跨模块变化通过领域事件和 Outbox 传递。

**本表与 README「逻辑模块与数据所有权」表一致，作为 Django app 数据所有权划分依据**：每张业务表唯一归属一个模块/app，其他模块通过应用服务或领域事件读写，禁止直接跨 app 更新他人所有的数据表；`workspace_access_sessions` 归工作区网关、`experiment_archives`/`experiment_archive_files` 归报告与审核、`compensation_jobs` 归实验编排。

成员资格校验是身份与授权模块对外的领域服务：任务发布筛选`ACTIVE`成员，任务启动在持久化实例事实前重新校验`ACTIVE`；成员退出或移除成功时发布会话撤销事件，工作区网关消费后撤销该成员全部活动会话。成员生命周期不由前端状态决定。

## 4. RuntimeAdapter 契约

```text
validate_spec(spec)
create(spec, idempotency_key)
get_status(runtime_instance_id)
get_progress(runtime_instance_id)
issue_access(runtime_instance_id, user_id, access_mode)
snapshot(runtime_instance_id, policy)
stop(runtime_instance_id)
destroy(runtime_instance_id, idempotency_key)
collect_metrics(runtime_instance_id)
```

`spec` 必须由服务端将冻结模板版本、任务策略、配额、白名单和安全策略组合生成，不接受普通用户提交的镜像、虚拟机模板、依赖、资源规格、路径或网络规则。适配器必须返回稳定的错误码、`retryable`、外部资源 ID、阶段进度和能力信息。

### 4.1 容器适配器

- 以 Docker Engine/OCI 为首个实现，镜像通过摘要锁定并经过白名单和漏洞扫描。
- 使用非 root 用户、CPU/内存/磁盘/进程/时长限制、默认拒绝网络和受控挂载。
- 工作区通过平台网关接入 WebIDE、Notebook、Web 终端和 Web 预览，不返回原始容器端口。

### 4.2 虚拟机适配器

- 使用 libvirt/KVM 和已扫描的系统盘模板；Cloud-init 只接收脱敏、最小化配置。
- 处理较长启动、系统盘快照、关机/停止语义、远程桌面或 Web 终端凭据和系统盘清理。
- 访问凭据短期有效且可撤销；虚拟机外部 ID、快照和事实状态必须可供补偿任务查询。

## 5. 异步与一致性架构

```text
API事务：业务状态 + Outbox + 审计
       -> Celery Worker 发布事件/调用 RuntimeAdapter
       -> SSE Gateway 推送阶段事件
       -> 失败进入 compensation_jobs
       -> 管理端重试或人工处置
```

- 成员申请、审核、直接添加、退出和移除，以及发布任务、报告保存/提交、审核、归档状态变化和会话撤销在同一业务事务内写 Outbox。
- Outbox 消费者按 `event_id` 去重；SSE 客户端按 `event_id` 和 `Last-Event-ID` 去重/续传。
- Celery 任务采用指数退避和最大次数；任务超限必须进入 `MANUAL`，不得无限重试。
- 运行时已成功但数据库提交失败、归档部分完成、配额释放不确定等场景写入补偿任务，由事实查询后再收敛。

## 6. 部署和环境

| 环境 | 部署内容 | 目标 |
|---|---|---|
| 开发 | Docker Compose：Web、API、Worker、MySQL、Redis、MinIO、Fake/Container Adapter | 可重复启动和本地契约联调 |
| 测试 | 与生产同拓扑的 API、Worker、网关、双 RuntimeAdapter、对象存储和监控 | 执行 E2E、性能、安全和恢复演练 |
| 预发布/UAT | 受控容器和 KVM 资源池，脱敏种子数据、真实凭据服务和告警 | 验证双运行时和用户验收 |
| 生产 | Web/API、Worker、网关、MySQL、Redis、MinIO、容器池、KVM 池分层部署 | 隔离故障域、备份、扩缩和回滚 |

生产最小备份为 MySQL 全量/增量、MinIO 版本与生命周期配置、代码/镜像清单和关键密钥引用。微服务拆分须有独立扩缩容、隔离或发布需求作为变更依据。
