# 06 开发规范与项目约束

**版本：** v1.0  
**状态：** 待审核的候选开发基线

## 1. 工程协作规范

- 采用主干开发或短生命周期功能分支；一个模块任务对应一个可审查变更集，不混入无关重构。
- 需求、状态机、API、数据库、UI 或验收变化必须先更新第三批章节和 `10_需求追踪矩阵.md`，再改代码。
- 所有数据库变化使用 Django migration；提供空库迁移、升级迁移、回滚/恢复说明，禁止应用启动隐式改表。
- 配置只从受控配置和密钥服务读取；禁止提交密码、令牌、云密钥、真实个人数据、生产导出和未脱敏日志。
- 新依赖必须记录版本、用途、许可证、镜像来源和漏洞扫描结果；镜像与运行时模板必须经过白名单。
- OpenAPI、JSON Schema、数据库迁移和测试 fixture 同步评审；接口契约未冻结前只允许 mock 联调。

## 2. 后端约束

- Django API/Serializer 层只处理认证、输入验证和响应；业务规则集中于 service/domain 层；运行时调用只能在 Adapter 层。
- 任意对象读取、更新、删除必须校验角色、资源归属、任务分配、时间窗口和状态迁移，不能只按主键查询。
- 任务发布只能选择当前`ACTIVE`成员；任务启动、工作区会话签发和关键任务读取必须重新校验成员资格，不能只使用发布时快照。
- 成员申请、审核、直接添加、退出和移除必须走服务层事务：锁定成员关系和阻断事项，写状态、会话撤销、通知、审计和Outbox；最后有效ORG_ADMIN保护由后端原子校验。
- 所有写接口记录 `request_id`、`trace_id`、操作者、对象、结果和幂等键；高风险操作额外记录审批上下文。
- 幂等事实以数据库状态、幂等记录和外部事实查询为准，不能依赖前端禁用按钮。
- Celery 任务必须设置超时、最大重试、指数退避、死信/人工处理入口和幂等保护；达到上限进入 `MANUAL`。
- 外部 RuntimeAdapter 调用必须设置连接/读取超时、稳定错误码、`retryable` 和操作幂等键；不得在数据库事务内等待。
- Outbox 与业务事实同事务写入，消费者按 `event_id` 去重；通知失败不能回滚已提交业务。
- Agent 工具调用按最小权限设计：命令、网络、文件系统、依赖安装和高风险动作均走策略层；禁止把用户输入拼接为 Shell 命令。

## 3. 前端约束

- React + TypeScript 使用严格模式；类型由 OpenAPI 生成或经过统一评审，禁止散落手写重复 DTO。
- 所有页面实现 loading、空、无权限、失败、可重试、异步成功、冲突、过期和危险操作状态。
- 任务页始终携带 `assignment_id`，实例/会话/报告页携带服务端对象 ID；刷新从服务端恢复上下文。
- 自动保存展示保存中、已保存、失败、冲突和最近保存时间；冲突不能静默覆盖。
- SSE 使用 `Last-Event-ID` 续传和 `event_id` 去重，断线后轮询降级；禁止前端本地计时器伪造最终状态。
- 不以隐藏按钮取代后端授权，不把角色、配额、状态机和销毁条件硬编码成唯一事实。
- Agent 悬浮控件必须有可见焦点、`aria-label`、文本提示和移动端避让；不能遮挡保存、提交、关闭和确认。
- 桌面 1440 px、平板 920 px、窄屏 390 px 均需验证，正文不能产生主体横向溢出；工作区内部按能力允许横向滚动。

## 4. 数据和安全约束

- 业务事实只存 MySQL；Redis 只用于锁、缓存、短期会话状态、限流和队列；对象正文只存 MinIO/S3。
- 访问令牌只在浏览器和网关短期存在；数据库仅存 JTI 摘要、用户、实例、模式、过期和撤销时间。
- 容器禁止 root、特权模式、宿主路径和 Docker Socket；虚拟机模板、Cloud-init、远程接入和网络均白名单。
- 上传文件执行类型、大小、扩展名、内容扫描和对象摘要校验；报告提交后附件关联不可修改。
- 日志、Agent 上下文、终端输出和错误响应必须脱敏；不得输出令牌、云密钥、SQL、内部地址或堆栈。
- 审核通过前不得销毁唯一报告、快照、关键日志和成果；归档摘要未校验不得进入销毁。
- 审计、版本、事件和补偿记录只追加；修正通过新事件表达，不允许删改历史。
- `team_memberships`及成员退出/移除相关的任务、报告、归档和审计历史不物理删除；成员状态失效后拒绝新分配、启动和工作区访问。

## 5. 质量门禁

| 变更类型 | 合入前最低要求 |
|---|---|
| 业务逻辑/状态机 | 单元测试覆盖正常、越权、状态冲突、重试、取消和部分成功 |
| 成员资格 | 申请、审核、直接添加、退出、移除、非ACTIVE启动拒绝、会话撤销、阻断事项和最后管理员保护 |
| API | OpenAPI 契约、鉴权、参数、幂等、ETag/revision、错误码和事件测试 |
| 数据库 | 空库/升级迁移、外键/唯一约束、事务回滚、备份恢复验证 |
| RuntimeAdapter | Fake、容器、虚拟机三类适配测试；创建、进度、访问、快照、停止、销毁幂等 |
| 文件/归档 | 上传扫描、摘要校验、预览、导出权限、归档清单和失败补偿 |
| 前端页面 | 主流程、冲突、断线恢复、桌面/窄屏视觉和可访问性检查 |
| Agent/安全 | 策略拒绝、高风险审批、上下文隔离、工具审计、依赖和敏感信息扫描 |
| 运维 | 指标、告警、Outbox/补偿、回滚、数据库与对象存储恢复演练 |

## 6. 禁止项

- 普通用户接口接受镜像、虚拟机模板、资源规格、宿主机路径、任意命令或运行时提供方。
- 通过前端路由、隐藏字段、调试接口绕过任务分配、版本冻结、审核或销毁前置条件。
- 把受邀请作为唯一加入路径，或允许非ACTIVE成员获取新分配、启动任务、签发工作区会话；以页面隐藏代替成员资格服务端校验。
- 将运行时、Agent、对象存储或数据库管理凭据下发至浏览器。
- 在同一代码路径混用 Django/DRF 与 FastAPI，或将 PostgreSQL/FastAPI/Celery 替代方案无审批带入主实现。
- 无限重试、无幂等外部调用、无事件去重的通知/事件消费者。
- 审核通过前销毁唯一成果，或删改审计、事件、报告和归档历史。

## 7. Python 编码风格

本节适用于本仓库所有 Python 源文件；自动生成文件、第三方代码和一次性迁移脚本可在文件头说明例外原因。代码以 Python 3.11+ 为基线，并以 `ruff format` 与 `ruff check` 的仓库配置作为可执行标准。

### 7.1 文件、模块和包

- 源文件使用 UTF-8、LF 换行和末尾一个换行符；禁止混用 Tab 和空格。
- 模块文件和包目录均使用全小写 `snake_case`，名称应表达领域或职责，例如 `runtime_adapter.py`、`assignment_service/`；禁止使用空格、连字符、拼音缩写和含糊名称，如 `util.py`、`common.py`、`test2.py`。
- 包目录必须有 `__init__.py`；`__init__.py` 仅用于公开稳定接口，不放业务逻辑或副作用。
- 测试文件命名为 `test_<被测模块>.py`，测试函数命名为 `test_<场景>_<预期结果>()`。

### 7.2 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块、包、函数、方法、参数 | 小写 `snake_case` | `create_assignment`、`request_id` |
| 局部变量 | 类型前缀 + 小写 `snake_case` | `i_retry_count`、`s_request_id`、`lst_member_ids` |
| 普通全局变量 | `g_` + 小写 `snake_case`，仅保存模块内部状态 | `g_service_name`、`g_active_tasks` |
| 模块级常量、枚举成员 | 全大写 `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT`、`TaskStatus.ACTIVE` |
| 类、异常、协议、类型别名 | `PascalCase` | `RuntimeAdapter`、`InvalidStateError` |
| 类属性和实例成员 | `m_` + 小写 `snake_case`，不使用类型前缀 | `self.m_request_id`、`self.m_created_at` |
| 受保护成员 | `m_` 后加单前导下划线 | `self.m__connection` |
| Python 名称改写的私有成员 | 双前导下划线后加 `m_`，仅限确有避免子类冲突需求时 | `self.__m_token_cache` |
| 布尔值 | 类型前缀 `b_` 后使用 `is_`、`has_`、`can_`、`should_` 语义 | `b_is_active`、`b_has_permission` |
| 集合 | 使用集合类型前缀，集合语义使用复数名 | `lst_member_ids`、`set_pending_task_ids` |
| 映射 | 使用 `dct_` 前缀，并用 `_by_`、`_to_` 或 `_map` 表达键和值 | `dct_task_by_id`、`dct_status_to_count` |
| 回调或处理函数 | 动词开头并带职责后缀 | `handle_event`、`on_task_completed` |

- 名称使用完整英文单词并反映业务含义。允许通用缩写 `id`、`url`、`api`、`ip`、`db`、`dto`；其他缩写首次引入必须可从上下文清楚理解。
- 变量命名按下表执行。局部变量必须有类型前缀；成员变量仅使用 `m_` 前缀；普通全局变量仅使用 `g_` 前缀。类型标注仍是类型信息的唯一依据。

| 类别 | 命名格式 | 示例 |
|---|---|---|
| 局部 `int` | `i_<语义名>` | `i_retry_count` |
| 局部 `float` | `f_<语义名>` | `f_completion_ratio` |
| 局部 `str` | `s_<语义名>` | `s_request_id` |
| 局部 `bool` | `b_<语义名>` | `b_is_active` |
| 局部 `list` | `lst_<语义名>` | `lst_member_ids` |
| 局部 `tuple` | `tpl_<语义名>` | `tpl_page_and_size` |
| 局部 `set` | `set_<语义名>` | `set_allowed_roles` |
| 局部 `dict` | `dct_<语义名>` | `dct_task_by_id` |
| 局部 `bytes` | `byt_<语义名>` | `byt_file_digest` |
| 局部 `datetime` | `dt_<语义名>` | `dt_created_at` |
| 局部 `date` / `time` | `date_` / `time_` + `<语义名>` | `date_due_on` |
| 局部 `Decimal` | `dec_<语义名>` | `dec_resource_quota` |
| 局部自定义对象 | `o_<语义名>` | `o_current_task` |
| 实例或类成员 | `m_<语义名>` | `self.m_request_id` |
| 普通全局变量 | `g_<语义名>` | `g_client_pool` |
| 模块级常量 | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT` |

- 函数参数使用无类型前缀的 `snake_case`，如 `request_id: str`、`retry_count: int`。局部副本则按本表命名。
- 不使用单字符变量，循环下标或数学公式中的 `i`、`j`、`x` 除外。禁止使用 `l`、`O`、`I` 作为变量名。
- 避免与内建名称冲突，例如 `id`、`type`、`list`、`dict`、`input`、`format`；确有外部契约限制时使用尾随下划线，如 `type_`。
- 不在函数外保存可变业务状态。模块级缓存、连接池或单例必须以前导下划线命名、保证并发安全，并在文档字符串中说明生命周期和清理方式。

### 7.3 函数、类和变量约束

- 函数名以动词开头，查询函数可使用 `get_`、`find_`、`list_`、`has_`；禁止以 `do_thing`、`process_data` 等模糊名称掩盖职责。
- 一个函数只完成一个可描述的业务动作。参数超过 5 个时，优先使用数据类、配置对象或关键字参数；禁止通过位置参数传递多个同类型且语义不同的值。
- 公共函数、类方法和跨模块函数必须为参数与返回值标注类型。仅在没有更精确类型可用时使用 `Any`，并在同一处说明原因。
- 使用 `T | None` 表示可空值，使用 `list[T]`、`dict[K, V]` 等内置泛型；运行时类型应来自 `collections.abc`，如 `Iterable[str]`、`Mapping[str, object]`。
- 数据承载对象优先使用 `@dataclass` 或 Pydantic 模型；避免以未约束的 `dict[str, Any]` 作为跨层接口。
- 实例成员在 `__init__` 或数据类字段中声明；方法中延迟创建的成员必须有明确类型并说明延迟初始化原因。
- 类常量使用 `ClassVar`；禁止把可变对象作为默认参数，使用 `None` 并在函数内初始化。

### 7.4 注释、文档字符串和日志

- 注释说明“为什么、约束或风险”，不重复代码显而易见的“做什么”。注释使用完整中文或英文句子，句末使用标点。
- 面向外部的模块、类、公共函数、复杂服务函数和 Adapter 必须提供三引号文档字符串，说明用途、重要参数/返回值、异常、权限或副作用；采用简洁的 Google 风格。
- `TODO`、`FIXME` 必须包含可追踪编号或负责人和完成条件，例如 `# TODO(PROJ-123): 在迁移后删除兼容分支。`；禁止无上下文的待办注释。
- 禁止通过注释保留废弃代码，历史由版本控制保存。临时兼容逻辑应标注移除条件。
- 日志使用参数化格式：`logger.info("Assignment created: %s", assignment_id)`；禁止拼接敏感数据、令牌、密码、个人信息、原始请求体或堆栈到业务响应中。

### 7.5 排版、导入和异常

- 每级缩进使用 4 个空格；禁止 Tab。行宽上限 100 个字符，格式化工具负责换行。
- 顶层函数与类之间留 2 个空行；类内方法之间留 1 个空行；逻辑分组可使用 1 个空行，禁止用连续空行分隔代码。
- 导入置于文件顶部，顺序为标准库、第三方库、本项目绝对导入，各组之间空 1 行；禁止 `import *`、未使用导入和函数体内导入（用于可选依赖或避免循环依赖时除外，并说明原因）。
- 使用明确异常类型和异常链：`raise DomainError(...) from exc`。禁止裸 `except:`，禁止无记录、无处理地吞掉 `Exception`。
- 比较单例使用 `is`/`is not`，如 `value is None`；布尔判断直接使用 `if is_active:`，不写 `== True`。
- 用上下文管理器管理文件、锁、连接和会话；用 f-string 构造普通字符串，日志仍使用参数化格式。

### 7.6 最低质量门禁

- 提交 Python 变更前必须执行 `py -m ruff format --check .` 和 `py -m ruff check .`；允许格式化时执行 `py -m ruff format .`。
- 代码评审必须检查命名是否反映领域、公开接口是否有类型与文档字符串、异常和日志是否保留足够上下文且不泄露敏感信息。
- 新增或修改业务逻辑时，测试名称遵循本节规则，并覆盖成功、边界、失败和权限/状态冲突路径。
