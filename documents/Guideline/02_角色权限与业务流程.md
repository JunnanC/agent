# 02 角色权限与业务流程

**版本：** v1.0  
**状态：** 待审核的候选开发基线

## 1. 固定角色与数据范围

| 角色编码 | 业务身份 | 允许动作 | 禁止动作 |
|---|---|---|---|
| `USER` | 普通用户 | 申请加入团队、查看成员状态、在无阻断事项时退出；查看本人任务、启动/取消装载、使用本人工作区、保存和提交报告/成果、使用受控 Agent、查看审核与归档 | 创建模板、发布任务、编辑环境方案、查看他人任务、管理成员或运行时 |
| `ORG_SUB_ADMIN` | 助教/授权教师 | 在授权任务范围内发布、查看过程、审核和导出 | 审核/添加/移除成员、修改全局配置、越权访问用户、管理固定角色 |
| `ORG_ADMIN` | 教师/团队管理员 | 审核加入申请、直接添加/移除成员；管理模板版本、发布/撤回任务、仅指定ACTIVE用户、审核、查看授权成果 | 管理运行时底座和全局安全策略 |
| `SYSTEM_ADMIN` | 系统管理员 | 管理账号、固定角色、管理员交接、运行时、镜像/虚拟机模板、配额、补偿、安全和审计 | 代替教师形成业务审核结论、绕过审计修改成果 |

前端路由和按钮只负责可用性，不能替代授权。后端每次读取或写入必须同时校验角色、数据范围、资源归属、任务状态、时间窗口和操作权限；不可仅凭资源主键返回数据。

## 2. 主流程

```text
用户申请加入或教师直接添加 -> ORG_ADMIN审核 -> 成员成为ACTIVE
-> 教师创建模板草稿 -> 环境/依赖/材料预检 -> 发布不可变模板版本
-> 创建任务并仅指定ACTIVE成员 -> 发布任务并生成通知
-> 用户进入任务 -> 自动装载容器或虚拟机 -> 签发工作区短期会话
-> 用户实验和持续保存 -> 提交报告或系统成果版本
-> 自动/人工/复合审核 -> 通过或退回重提
-> 固化报告、附件、快照、日志、评测和产物 -> 校验归档摘要
-> 撤销全部访问会话 -> 销毁运行时 -> 释放配额 -> 完成
```

## 3. 团队成员资格状态机

```text
未加入 -> PENDING -> ACTIVE -> EXITED
                 -> REJECTED
ACTIVE -> REMOVED
```

- `PENDING` 由USER提交申请产生；ORG_ADMIN审核通过变为`ACTIVE`，拒绝变为`REJECTED`；ORG_ADMIN直接添加可直接创建`ACTIVE`记录。
- `ACTIVE`成员可接收新任务分配；任务发布与任务启动均重新读取成员资格。`PENDING`、`REJECTED`、`EXITED`、`REMOVED`均不能接收新分配或启动任务。
- USER退出与ORG_ADMIN移除都必须检查未完成任务、活动实例、待审核/归档/销毁流程；存在任一项返回阻断清单，不变更成员状态。
- 成功退出或移除时，同一事务追加成员历史、撤销所有`ACTIVE`工作区会话、写通知/审计/Outbox。最后一名有效`ORG_ADMIN`受保护，只能由SYSTEM_ADMIN先完成管理员交接。

## 4. 用户任务状态机

### 4.1 正常状态

```text
ASSIGNED -> PROVISIONING -> READY -> IN_PROGRESS

report_required = true:
IN_PROGRESS -> REPORT_DRAFT -> UNDER_REVIEW
                              -> REJECTED -> REPORT_DRAFT
                              -> APPROVED

report_required = false:
IN_PROGRESS -> UNDER_REVIEW    # finish 时生成系统成果清单版本
              -> REJECTED -> IN_PROGRESS
              -> APPROVED

APPROVED -> ARCHIVING -> DESTROYING -> COMPLETED
```

`finish` 不能绕过审核。报告必交任务提前结束时先保存草稿和必要快照，停止交互环境后仍停留在 `REPORT_DRAFT`；非必交任务执行 `finish` 时冻结系统成果清单版本并进入 `UNDER_REVIEW`。

### 4.2 失败与取消

异步阶段失败时，聚合状态进入 `FAILED`，同时保存 `failure_stage`、`previous_status`、错误码、脱敏原因、`retryable`、重试次数和 `trace_id`。恢复规则如下：

| 失败阶段 | 自动/人工恢复目标 | 最大自动重试 | 超限处理 |
|---|---|---:|---|
| `PROVISIONING` | 原装载任务的可恢复步骤，成功后进入 `READY` | 3 | 标记人工处置，可重试或取消并释放配额 |
| `ARCHIVING` | 同一归档记录，成功后进入 `DESTROYING` | 5 | 禁止销毁，转人工补齐或确认成果 |
| `ACCESS_REVOKE` | 继续撤销活动会话 | 5 | 封禁网关访问并转人工处置 |
| `DESTROYING` | 同一运行时资源销毁操作 | 10 | 转人工核验运行时事实状态 |
| `QUOTA_RELEASE` | 重新核对实例与配额事实后释放 | 10 | 转人工处置，禁止重复释放 |
| `OUTBOX_PUBLISH` | 重发同一 `event_id` | 10 | 转人工处理，消费者继续按事件去重 |

任务撤回进入 `CANCELLED`：禁止新启动；装载中的任务先取消装载并清理资源；运行中的任务按撤回策略保存草稿和快照、撤销会话并回收；已进入审核、归档或完成的记录不物理删除，只追加撤回/关闭审计事件。

## 5. 实例、报告和归档状态

```text
实例：REQUESTED -> PROVISIONING -> READY -> RUNNING -> STOPPED
                     |                         |          |
                     +-> FAILED <--------------+          +-> DESTROYING -> DESTROYED

报告：DRAFT -> SUBMITTED -> UNDER_REVIEW -> APPROVED
                         |                 -> REJECTED -> DRAFT(新版本)

归档：PENDING -> ARCHIVING -> COMPLETED
                       |-> FAILED -> ARCHIVING(重试)

访问会话：ACTIVE -> EXPIRED
                 -> REVOKED
```

- 已提交报告版本、已审核版本和已完成归档均不可覆盖。
- 报告自动保存只更新当前可编辑草稿及其并发修订标识；提交时生成并冻结业务版本。
- 归档只有在清单存在、全部文件摘要验证通过且状态为 `COMPLETED` 后才能触发销毁。
- 实例停止、用户禁用、成员退出/移除、任务撤回或销毁开始时，所有 `ACTIVE` 工作区会话必须转为 `REVOKED`。

## 6. 核心异常流程

| 场景 | 系统处理 | UI 反馈与恢复入口 |
|---|---|---|
| 重复启动或页面刷新 | 按分配记录和幂等键复用实例及装载任务 | 恢复当前步骤，不创建第二个实例 |
| 装载失败 | 保留已完成步骤和日志，按同一任务断点重试 | 显示失败步骤、原因、`trace_id`；仅 `retryable=true` 显示重试 |
| 用户取消装载 | 停止后续步骤，销毁已创建资源并释放锁定配额 | 展示取消中、已取消或清理失败 |
| SSE 断线 | 使用 `Last-Event-ID` 续传并按 `event_id` 去重；失败时轮询 | 页面恢复同一进度，不倒退或重复弹窗 |
| 工作区令牌过期 | 拒绝旧令牌，在授权仍有效时申请新会话 | 提示重新连接；已保存内容不丢失 |
| 报告保存冲突 | 拒绝覆盖并返回服务端最新 ETag/修订 | 用户选择加载最新内容或另存为新草稿版本 |
| 报告退回 | 冻结被退回版本，创建后续可编辑版本并通知用户 | 展示证据、评分、评语和退回原因 |
| 任务撤回 | 写撤回事件与通知，根据阶段保存和回收 | 展示撤回原因、可下载成果和回收状态 |
| 归档失败 | 保持实例不可销毁，补偿重试同一归档 | 展示归档失败和处理中，不显示已完成 |
| 运行时已删除但数据库失败 | 记录补偿任务，查询运行时事实后收敛状态 | 管理端显示部分成功和人工处置入口 |
| 通知目标失效 | 打开前重新鉴权并校验对象 | 显示目标已失效，不泄露原对象内容 |
| 用户退出团队 | 先检查阻断事项；无阻断时变更为`EXITED`并撤销会话 | 有阻断时展示事项和处理入口；成功后任务入口失效 |
| 教师移除成员 | 仅ORG_ADMIN可操作；先检查阻断及最后管理员保护 | 显示不可移除原因或移除完成通知，不能由助教操作 |

## 7. 审核规则

| 模式 | 输入 | 结论形成规则 |
|---|---|---|
| `MANUAL` | 冻结报告/成果版本、附件、快照、日志、产物 | 授权教师填写评分、评语并通过或退回 |
| `AUTO` | 冻结版本与评测结果 | 全部强制规则通过才自动通过；失败按任务规则退回或转人工 |
| `COMBINED` | 自动评测结果和人工证据 | 自动评测先完成，教师结合结果形成最终唯一结论 |

同一提交版本只能形成一条最终审核记录。并发审核时后到请求返回状态冲突和最新结论，不得覆盖。

## 8. UI 与可访问性约束

- 实验列表、装载、工作区和报告页始终提供 Agent 入口；任务上下文切换后必须同步切换 Agent 上下文。
- 装载、归档和销毁使用同一阶段时间线表达等待、处理中、成功、失败和可重试状态。
- 工作区固定提供实验手册、起始资源、结果区和流程入口，关键操作不得被悬浮控件遮挡。
- 悬浮 Agent 支持鼠标、键盘焦点、`aria-label` 和文本提示；移动端自动避让底部操作区。
- 停止、提前结束、撤回和强制销毁必须二次确认，明确保存、快照、访问中断和不可逆影响。
- “我的团队”页必须展示成员状态、申请处理说明和退出阻断事项；非ACTIVE成员任务页显示资格原因与团队入口。
- “团队成员”页仅对ORG_ADMIN可见，支持状态筛选、申请审核、按账号直接添加和移除确认；移除确认必须显示阻断事项及最后管理员保护。
