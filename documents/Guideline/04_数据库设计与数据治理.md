# 04 数据库设计与数据治理

**版本：** v1.0  
**状态：** 待审核的候选开发基线  
**字段权威来源：** `documents/Preparation/附件5：数据库设计文档.docx` v1.0

## 1. 设计原则

- 以数据库设计文档 v1.0（`documents/Preparation/附件5`）为字段、索引、外键、状态和事务权威，不在第三批重新发明字段；历史批次版本仅保留为迁移前字段对照。
- 平台为单团队，角色固定为 `SYSTEM_ADMIN`、`ORG_ADMIN`、`ORG_SUB_ADMIN`、`USER`，不建立课程、班级、训练营或自定义角色表。
- 模板主体、模板版本、教师任务、用户分配、运行实例、报告版本、审核、归档和文件必须分离。
- 文件正文和大对象放入 MinIO/S3；数据库保存元数据、归属、状态、哈希、引用和审计索引。
- 所有业务主表含创建/更新时间；审计、事件和版本只追加，不原地覆盖。
- 业务事务只提交本地事实；外部运行时、通知和事件投递通过 Outbox、Worker 和补偿任务完成。

## 2. 领域数据模型（v1.0）

| 领域 | 核心表 | 关键规则 |
|---|---|---|
| 单团队与身份 | `team_settings`、`team_memberships`、`users`、`roles`、`permissions`、`role_permissions`、`user_verifications`、`user_quotas` | 账号、角色与成员资格分离；成员状态为PENDING/ACTIVE/REJECTED/EXITED/REMOVED；角色预置只读；配额按用户维护 |
| 文件 | `files` | `object_key`、内容摘要和 MIME 元数据；文件可被材料、报告、快照和归档复用 |
| 模板与任务 | `template_categories`、`experiment_templates`、`experiment_template_versions`、`template_assets`、`template_env_vars`、`experiment_tasks`、`experiment_task_assignments`、`task_materials` | 发布任务冻结模板版本，仅向ACTIVE成员分配；`(task_id,user_id)`唯一，分配保存`team_membership_id`快照；材料类型含手册、起始模板、数据集、附件 |
| 实例与装载 | `experiment_instances`、`instance_provisioning_jobs`、`instance_provisioning_steps`、`instance_events`、`instance_resource_stats` | 实例必须归属分配记录；任务和步骤具幂等键；运行时类型为 `CONTAINER` 或 `VIRTUAL_MACHINE` |
| 实验记录与产物 | `experiment_records`、`experiment_artifacts` | 保存代码、配置、运行输出、指标、日志和快照的元数据与对象引用 |
| 报告与审核 | `experiment_reports`、`experiment_report_versions`、`experiment_report_files`、`experiment_report_reviews` | 草稿可编辑；提交版本、附件和审核结果不可覆盖 |
| 成果归档 | `experiment_archives`、`experiment_archive_files` | 每个任务分配最多一份最终归档；清单 SHA-256 校验通过才可销毁 |
| 工作区会话 | `workspace_access_sessions` | 只存 JTI 摘要；绑定实例、用户、接入方式和过期/撤销状态 |
| 通知与可靠性 | `notifications`、`compensation_jobs`、`outbox_events` | 通知由 Outbox 消费生成；补偿和事件按幂等键/事件 ID 去重 |
| Agent 与评测 | `agent_runs`、`assistant_conversations`、`assistant_messages`、`tool_call_logs`、`model_providers`、`model_call_logs`、`evaluation_rules`、`evaluation_jobs`、`evaluation_results`、`audit_logs` | 评测可作为审核输入；模型和工具调用均必须可追溯，基础评测结果可审计 |

## 3. 核心聚合与生命周期

```text
experiment_templates -> experiment_template_versions
       -> experiment_tasks -> experiment_task_assignments
       -> experiment_instances -> workspace_access_sessions
       -> experiment_reports -> experiment_report_versions
       -> experiment_archives -> experiment_archive_files
```

`team_settings -> team_memberships -> experiment_task_assignments`。`team_membership_id`保存发布时有效成员关系快照；任务启动仍按当前`team_memberships.status=ACTIVE`校验，快照不替代实时授权。

- `experiment_task_assignments` 是用户流程聚合根，承载任务状态、失败阶段、提交、审核和完成时间。
- `experiment_instances` 只能通过分配记录创建；不能按用户 ID 加模板 ID 绕过任务。
- `experiment_report_versions` 的 `(report_id, version_no)` 唯一，提交后正文、附件关联和快照清单不可修改。
- `experiment_archives.task_assignment_id` 唯一；`experiment_archive_files` 保存来源、归档角色、内容摘要和最终文件关系。
- `workspace_access_sessions.token_jti_hash` 唯一，任何会话失效都记录撤销时间。

## 4. 必须落实的事务

| 业务操作 | 同一事务内提交 | 异步后续 |
|---|---|---|
| 成员申请/变更 | 成员关系、状态、会话撤销事实、审计、通知 Outbox；移除同时检查阻断事项和最后有效ORG_ADMIN | 网关会话撤销、通知投递 |
| 发布任务 | 任务、仅ACTIVE成员的用户分配、`team_membership_id`快照、审计、通知 Outbox | 生成站内通知 |
| 启动实验 | 分配/时间/配额校验、幂等键、配额锁、实例和装载任务 | 创建运行时、挂载、依赖、健康检查 |
| 保存草稿 | 报告主记录、草稿版本、附件关联、修订号 | 对象存储上传确认和病毒扫描 |
| 提交报告/成果 | 版本冻结、附件、快照清单、任务状态、审计、通知 Outbox | 自动评测和教师待办 |
| 审核 | 审核记录、报告/任务状态、审计、通知 Outbox | 归档编排 |
| 归档 | 归档主记录、归档文件关系、清单摘要、任务状态 | 对象复制/校验、完成后触发销毁 |
| 会话撤销 | 会话状态、任务/实例事实、审计 | 网关撤销缓存刷新 |
| 回收 | 凭据撤销事实、销毁状态、配额释放标记、事件 | 运行时删除；失败写补偿 |

Outbox 行必须与业务事实在同一事务内写入；消费者以 `event_id` 去重。配额释放先写业务事实和幂等标记，再执行外部动作，禁止重复扣减或释放。

## 5. 报告、成果和非必交任务

- `report_required=true`：报告正文、附件、快照和关键日志组成提交版本，由用户提交。
- `report_required=false`：用户结束时由编排服务创建系统成果版本，正文可为空但必须包含快照、运行结果、日志和产物 manifest，审核记录仍必需。
- 附件上传先入对象存储临时区，完成类型/大小/病毒扫描后才写 `experiment_report_files`；提交后关联不可增删。
- 归档文件包括通过版本正文、附件、快照、日志、评测结果和必要产物；每个文件保存 SHA-256，manifest 保存整体摘要。
- 归档状态不是 `COMPLETED` 或摘要校验失败时，不能进入访问撤销和销毁。

## 6. 数据安全、留存和恢复

- 密码使用不可逆强哈希；API 密钥、工作区令牌、远程桌面密码只使用密钥服务或短期令牌，不写入业务表明文。
- 操作日志、终端日志、Agent 上下文和附件在对象存储/日志系统前脱敏；不记录完整令牌、云密钥、个人敏感信息。
- 默认保留：归档 365 天、审计 180 天、运行日志 30 天；任务策略可延长但不能低于系统/法定下限。
- 删除采用状态和生命周期策略控制；物理删除前确认没有外键、归档和审计义务，并追加删除事件。
- 成员退出或移除不删除`team_memberships`、历史分配、报告、归档或审计记录；只有当前资格失效，后续启动和会话访问被拒绝。
- MySQL 每日全量、连续增量和每月恢复演练；MinIO 开启版本与生命周期策略，抽样验证归档对象可读和摘要匹配。

## 7. 禁止实现方式

- 将课程、班级、报告或运行配置堆入 `users`、`experiment_instances` 的不可检索 JSON 大字段。
- 将 Redis、前端缓存或实例临时磁盘作为任务、报告、审核、配额或成果的唯一事实来源。
- 直接以用户 ID 和模板 ID 创建实例，绕过 `experiment_task_assignments`。
- 原地覆盖已提交报告、审核结论、归档清单、事件或审计日志。
- 在数据库保存明文工作区令牌、远程桌面密码、云密钥或完整 Agent 敏感上下文。
